# 核心记忆 · DND 角色卡

这是开发决策入口，不是进度流水账。当前用户指示优先；版本和任务状态只在 [CURRENT.md](CURRENT.md) 更新。

## 八条底线

1. **改哪里，处理哪里。** 先列变化对象、字段和真实依赖。文字编辑不重算规则，库存位置不重建物品，切页不重建角色。只传播至确实受影响的依赖。
2. **保留未变内容。** 复用条目、索引、界面及有效缓存；不靠全卡深拷贝、清空重建或每次全量哈希制造“干净状态”。首次导入、恢复、明确规则版本变化及显式完整校验可以全量处理，须限定范围并避开交互热路径。
3. **玩家资料只有一份权威。** 来源快照、选择、运行资源、界面状态各有归属。手填数据、未知字段和已花次数不能被刷新、来源恢复或同步接管、删除、补满。导入先校验；关联扣费与回执原子提交，失败保留旧值和草稿。
4. **缓存不是权限。** 提交时核对当前角色、账号／房间、写权限、版本与请求身份。拒绝过期回调和重复操作；不能跳过授权、冲突或持久确认求快。成功提示必须对应实际本机保存或远端确认。
5. **规则正确性不能换速度。** 2014／2024、不同来源身份分开；由核验数据和纯执行器判断，不按显示名称特判。未知显式待核实，手动卡自由编辑；局部机制不算整条、整书或全目录完成。
6. **先测真实操作。** 分开量下载、解析、计算、渲染、保存，记录调用次数与影响对象数。发布版、诊断版、模拟数据、玩家原卡、真机和多人分别报告。嵌套耗时不相加，单次测量不冒充普遍结论。
7. **先复现，小步改，再证明。** 保留首次失败、跳过和未执行；不改时限、断言、散列或分母求通过。一次一个机制，跑相关回归；共享规则核心按准确代码／数据重放，不拿旧报告认证新代码。
8. **保住现场和发布边界。** 不覆盖原脏树，不动玩家原件，不公开私人资料、规则全文或密钥。使用隔离工作区。推送、合并、部署、线上验证分别记；未知结果先查回执，不盲目重复发布，不绕平台保护。

## 项目边界

保留灰色粗框、切角、五页、状态效果、填入链接与选择；默认 A4 及已存响应式偏好按当前产品约定，打印／图片保持 A4。不为优化换成通用仪表盘；手动模式不新增配额门槛。规则计算独立于 React、存储和原生接口。中文执行会话提供的 `chinese-writing-style` 技能。

只有背景、种族、职业、子职、体型使用动画虚线外框，隐形状态例外按状态正本；编辑恢复正常布局。UI 反馈提供本地截图，按批验证和发布，不逐次视觉修改就推送。

本轮不配置或使用 OpenAI API、不索取 Key、不嵌入玩家 AI。不修改 Godot／原生参考应用，C++ 留待后期，不搭猜测中的平台框架。枭熊先查实际依赖，独立版稳定后再对齐，不能直接覆盖其权限、存储或协议。

长期授权允许正常开发、合格后的推送／合并与既有流程发布；不覆盖用户当次“仅审阅、不改代码、不上线”的限制。核实当前权限，不能把历史管理员障碍永久当成现状。

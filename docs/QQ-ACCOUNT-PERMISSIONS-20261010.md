# QQ 账号卡库与房间编辑

本次为 QQ 正式接入后的权限准备。真实 QQ 登录仍需腾讯审核完成后验收；`qqLogin: ready` 只表示后端配置齐全。

## 账号卡库

- 登录账号只能列出自己的卡和卡主明确授权的卡。未获授权的账号和访客按 ID 读取账号卡时返回 404。
- 每个账号有 10 个免费槽位，由服务端计算。编辑别人授权的卡不占自己的槽位；只有卡主可授权、撤销或删除原卡。授权对象使用登录后复制的账号 ID，不能把 OpenID 当成 QQ 号码。
- 原浏览器上传的临时卡可明确确认后迁移到当前 QQ 账号，保留卡片 ID 和内容。迁移同时检查原浏览器所有权、版本和账号槽位，不能冒领公开卡。
- `temporary-ip` 继续允许访客浏览临时公开卡，登录后始终只显示账号卡库。QQ 验收后以 `DND_CLOUD_MODE=account-private` 关闭匿名上传和公开目录。旧站 JSON 导出入口保留。
- 支付尚未接入，不能声称额外槽位已可购买。

## 枭熊插件

网站完成真实 QQ 登录并确认连接后，插件通过一次性 PKCE 连接取得独立会话。连接采用轮询，支持登录服务隔离弹窗 opener 的情况，不依赖 iframe 第三方 Cookie。插件会话绑定允许的页面来源，随网站会话失效或退出而撤销。

卡主将自己的卡加载到房间后默认锁定。只有卡主能解锁、重新锁定或移出房间。解锁后，房间成员无需再获得卡库权限，就能修改该张卡；每次保存自动写回同一张云端原卡。移出房间不删除原卡。

房间信息仅保存该张卡的随机授权凭据，绝不保存个人登录令牌。房间 ID 和枭熊玩家 ID 都不作为 QQ 身份。凭据有效期为 7 天，重新加载会更换凭据并重新锁定。权限依靠持有凭据访问一张卡；枭熊客户端 API 没有提供服务端可验证的房间成员证明，因此复制出去的凭据在失效或撤销前仍可读取这张房间卡，解锁时也可修改它。它不能读取个人卡库或其他卡。

## 自动写回与恢复

QQ 卡的背包直接保存在云端原卡，不进入旧插件的独立库存账本。当前 QQ 卡不接入旧公共库存的跨容器转移或赠予，避免旧库存覆盖原卡。

所有写回检查原卡版本。并发冲突返回 409，重新锁定后拒绝成员写回，并在接收请求内容后再次核对授权。没有静默覆盖或自动重试修改。

五页编辑器单独保存房间草稿，失败和冲突后刷新仍可恢复。核对云端版本会先导出草稿并保留恢复记录，再读取当前原卡。其他成员的成功提交会在空闲且无待保存草稿时刷新当前卡。

## 发布与验收

本分支包含服务端、网站、插件登录页与房间编辑所需的接口；Suite 开发版和稳定版分别移植入口。测试只使用本地 SQLite 和合成账号，不提供线上模拟登录。

正式启用须分别完成真实 QQ 登录、浏览器账号切换、卡主与另一位房间成员的读取和编辑、自动写回、重新锁定、冲突恢复以及旧站导出验收。构建和本地模拟浏览器检查不等于这些验收已完成。启用时沿用持久数据库，先备份数据库与每个发布目标，并保持现有站点、玩家数据和服务配置的边界。

启用分两步：先以 `temporary-ip` 安装本版本的隐私后端，核对健康接口的 `accountLibrariesPrivate: true` 和 `permissionsVersion: 1`；真实 QQ 验收通过后，再用密封发布包的 `cloudMode: account-private` 和对应服务配置启用账号模式。发布器会检查匿名上传、公开目录和账号额度，并要求之前的后端已保护账号卡，确保回滚也不会暴露私有卡。

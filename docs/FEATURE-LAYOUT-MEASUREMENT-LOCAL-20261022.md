# 跨卡特性布局测量，本地独立候选

本项接续 `0895413`，与 Tooltip 和紧凑提示分别提交。仅改 `FeaturePanel.tsx` 的动画基线测量；没有修改 `App`、`PaperFrame`、角色数据或规则行为，也没有推送、合并或发布。

## 原因与处理

旧实现虽然用角色 ID 阻止跨卡入场动画，但检查发生在每条特性的 `getBoundingClientRect` 和 `offsetWidth` 之后，因而仍在提交阶段逐行读取布局。

新实现切卡先清理旧位置；首次绘制后，通过两次动画帧回调建立当前卡的无动画基线，只读取矩形，不再为初始基线读取宽度。切卡、切页、捕获或卸载会取消旧回调；执行前再次检查根节点、连接状态和角色 ID。减少动态效果或捕获时不测量这套动画基线。

若玩家在基线建立前立即展开或重排，则在这次明确编辑之前采样当前卡，保留首次同卡过渡。正常同卡动画、选择入口和保存结构沿用原行为。

## 浏览器证据

使用同一实际 App、独立本地服务器和原创隔离夹具，两张卡各有 120 条特性。没有连接正式账号或导入玩家文件。

| 六次真实角色标签切换 | 修改前 | 修改后 |
| --- | --- | --- |
| 提交阶段每次矩形读取 | 120 | 0 |
| 提交阶段每次宽度读取 | 120 | 0 |
| 绘制后每次基线矩形读取 | 0 | 120 |
| 本轮提交耗时范围 | 59.3–69.3 ms | 最终组合 84.2–112.1 ms |
| 本轮双帧绘制观测范围 | 106.8–134.2 ms | 最终组合 147.9–176.6 ms |

**绝对耗时在本轮没有改善。** 原布局读取累计仅约 0.3–0.6 ms，占切卡耗时很少；修改后多轮结果也有波动，同机同时进行其他验证，不能把这项候选当成主要卡顿已解决或整体提速。后续公平整合比较仍需在同机器、同顺序执行 A–B–B–A；本项没有停止其他任务，也没有设置或放宽耗时断言。

前后原始报告和最后组合报告仅在本地保留。每次逐行调用、阶段、耗时和角色身份均保留，不公开私人测试卡的身份或记录。

最后组合 4 条浏览器流程全部通过，包含：

- 同卡首次展开和 Alt 方向键重排仍产生实际变换动画；切卡后一帧内立即展开也保留过渡。
- 8 次逐帧快速切卡后卸载详细页，没有读取已断开或非当前卡节点。实际仍需存在的通用状态条不被误当成详细特性页。
- 导出中途切卡正确中止并清理；随后实际生成 2480×3508 PNG，恢复已展开的正文与屏幕布局。
- 减少动态效果下，切卡不读取这套特性布局、同卡操作不创建动画。
- 既有两条详细页展开／收起、保存恢复和未选选择流程继续通过。

4 项特性版式单测、TypeScript 与差异空白检查通过。已检查导出恢复后的截图。首轮过渡检查把通用状态条包含在“详细页应卸载”的选择器里，其失败保留在 `feature-motion-transitions`；修正范围后没有放宽节点连接、角色身份、动画或导出断言，单独及最终组合均通过。

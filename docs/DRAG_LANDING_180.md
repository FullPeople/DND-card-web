# 接收区域与拖拽落点（本地）

2026-09-23。修复 Wiki、公共仓库和状态气泡落到角色／怪物／总览时，预览被扩展为整张接收卡的问题。没有改动原 A4 状态效果、同步协议或持久化格式。

## 原因与处理

`EntryDragProvider` 在接收后未找到对应条目时，原先把整个 DropZone 当作动画目标。库存转移有类似容器回退；总览状态转交还会回退到整行状态区、整行标题。`pointerDrag` 对复制源外观的预览未限制目标尺寸，其他预览也可能选中很宽的标题，因此接收已成功时依旧会把小条目撑成大矩形。

现在 `Landing.region` 只表示接收区域：保留拿起时的宽高，在该区域内靠近松手点落位。`resolve` 只查找真实条目、物品空格或同一状态气泡，不再返回整行标题／整张卡。最终目标过宽、过高、不可见或已经卸载时，统一回退到区域小落点；不会隐藏接收卡或把卡的外观复制到预览。正常的 3 度倾斜、220 ms 落位和真正物品格到装备／同调气泡的 morph 保留。

`DropZone` 同时支持传递普通 div 属性，怪物主卡的库存／状态接收标记因此能直接参与 `closest` 命中。自身 ref、注册 ID 和兼容性样式保持由 DropZone 管理。

## 验证

`tests/e2e/drag-landing-180.spec.ts` 使用真实 Pointer Events、生产 UI 与真实 workbench 请求入口，模拟宿主确认数据。逐帧记录拿起及落位期间的预览宽高，并记录 Web Animations 的首尾关键帧；既检查尺寸边界，也检查目标收到的物品／状态。

- 1400 px、420 px 总览：Wiki 物品、公共仓库物品、状态气泡转交和 Wiki 状态。
- 怪物总览：Wiki 物品、仓库物品和 Wiki 状态。
- 实际怪物背包：Wiki 物品进入真实库存格。
- 900 px、420 px 怪物主卡：Wiki 物品与状态；切到背包后物品仍存在。
- 实际人物背包：物品缩成装备气泡，背包物品保留，刷新后装备标记保留。

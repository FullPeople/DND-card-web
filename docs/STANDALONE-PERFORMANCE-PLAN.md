# 独立角色卡性能审阅与优化方案

2026-11-07。本轮只审阅与整理文档，不修改功能代码、存储格式、权限、协议或线上文件。覆盖独立版全部操作；不是只优化骰子或单页。插件对齐是后续待办。

## 已确认的结构问题

基线为实际公开 `standalone-1.0.311`／源码 `8fb3815ba4dbb72d8901be3f6b723ca447d4d5ea`。本轮查询 main 为 `0ed1741e0c0f13b837425baadcaa380279945e1f`。最新本地法术位候选没有上线，不能将当前线上问题归咎于该候选。

1. **故事走规则编辑入口。** `src/ui/CharacterPages.tsx:BackgroundPage` 的背景故事、描述等普通回调进入 `src/ui/App.tsx:edit`。名字有明确的 `displayCharacterEdit`，故事没有。每次输入都会走整卡复制、特性／法术／资源同步。
2. **修改后重复核对。** 通用编辑令嵌套对象全部换身份，破坏对象缓存；`sameCharacterMechanics` 将引用变化视为机制变化，`reconciledCardView` 又复制、又同步。`sheetChoices` 构造与文字无关的候选，并在内部反复计算角色数值。
3. **保存读写整本角色簿。** `saveWorkspace` 读取旧整本、保存整本备份，再写新整本。40 ms 队列能合并部分保存，没有消除前面重复计算，也没有变成按角色保存。
4. **首屏静态依赖较重。** 实际公网核心脚本解压后为 7,481,358 字节。静态源码依赖闭包中 JSON 源文件合计 7,878,953 字节，普通施法证据约 3.52 MB。物品归属模块为使用身份集合也静态引入该整份证据。源码字节、解压字节与网络传输字节不是同一口径。
5. **资料发布耦合整本准备。** `load` 在发布新目录前调用 `prepareStandaloneCatalog`，准备全部已存角色并建引用索引；编辑改变角色数组时，上下文可能失效并重新尝试。它也有逐卡缓存，不能因此说每次都会重算其他所有角色。空闲阶段虽会让步，单个阶段仍可阻塞主线程。

原因不是单纯“没有缓存”，而是通用回调未声明变化范围，为一致性统一协调整卡；更多机制后来接入，简单操作也承担其成本。轻量路径覆盖不全，完整复制又使已有缓存失效。

## 实测与适用范围

全新匿名浏览器，API 写入隔离，没有账号或玩家原卡。受控输入为逐字节核验的私有 229 份资料，界面读取 29,505 条内容。自制卡先有 30 件物品、20 条特性、100 个法术，再经正常界面加入真实目录中的法师、升至 12 级，最终 163 个选择；不公开原始正文。

| 操作 | 未插入规则计数的实际公网版本 | 同源码诊断版本的调用观察 |
|---|---|---|
| 修改法师卡故事一次 | 至保存约 798 ms；输入至后续两次动画帧约 741 ms | 两次整卡复制；特性／法术／资源各同步两次；11 次 `evaluate`、11 次 `sheetChoices` |
| 连续输入十个字符 | 至保存约 6,031 ms；每次输入至两次动画帧约 560–625 ms | 20 次复制；三类同步各 20 次；101 次 `evaluate`、91 次 `sheetChoices` |
| 尚未加职业的同一自制卡，改物品数量 | 约 508 ms，含点击、输入和提交 | 三次整卡复制，三类同步各两次 |
| 尚未加职业的同一自制卡，拖入一件装备 | 约 450 ms，含拖放 | 三次整卡复制，三类同步各两次 |
| 另一次独立公网冷启动，空白卡 | 首张卡约 30.74 秒；核心脚本请求约 27.76 秒，传输约 1.30 MB | 单次网络样本，不与上面的受控目录计时相加，不代表所有线路 |

这是诊断样本，不是总体统计或原设备验收。两次动画帧只是显示响应的代理指标，不等于像素验收。同步、选择与计算存在嵌套，计时不能相加；保存的等待不等于纯 CPU 时间。没有证明每次打字都下载全库、重建全部目录索引或销毁整个页面。

[安全测量摘要](data/standalone-performance-baseline-20261107.json) 包含原始报告散列。早期诊断脚本两次误以为导入保留原角色 ID；实际产品正常生成新副本。准备失败保留，未计为产品失败；后改为检查新副本及 150 条内容，原 60 秒时限保持。

## 全场景的变更范围

局部更新指目标及其真实依赖闭包。施法可能同时关联法术位、来源次数和回执，不能为少改一个字段拆开必要事务。

| 场景 | 应处理 | 不应顺带处理 | 查代码入口 |
|---|---|---|---|
| 故事、背景描述、展示字段 | 对应字段、显示、修订／历史／可靠保存；先确认字段无规则依赖 | 规则求值、三类同步、候选重建、全卡复制 | `src/ui/CharacterPages.tsx`、`src/core/displayCharacterEdit.ts`、`src/ui/App.tsx:edit` |
| 物品数量、金币、库存位置 | 目标库存行；数量影响负重等依赖，位置只改布局 | 全部职业特性、全部候选、未变物品快照 | `src/ui/InventoryPage.tsx`、`src/ui/StockBoard.tsx`、`src/core/inventory.ts` |
| 装备、卸装、同调、物品特性 | 目标及其授予、AC／攻击等真实依赖；考虑组合效果 | 无关法表、其他角色、全部资源恢复 | `src/core/automation/equipment.ts`、`src/core/sheet.ts`、`src/core/engine.ts`、对应物品机制 |

## 分批实施

### 第一批：文字和重复核对

- 沿已有明确编辑意图补齐经验证的纯展示字段，只复制目标所在小对象，未变选择、条目和配置保留引用。不能根据任意回调或字符串 key 猜测安全。
- 权限核对后，明确无变化的操作直接返回，不记新历史、不保存、不协调；避免“设为原值”也触发完整流水线。
- 一次机制修改只协调一次，结果绑定实际规则上下文，读取视图复用。旧卡恢复、版本变化及首次校验仍要执行，不能凭“刚改过”跳过。
- 选择候选按真实机械输入及版本缓存；文字、整卡引用或 `revision` 不作为其单一失效条件。证据／规则快照缓存须验证不可变内容，不能仅按显示名或条目 ID 复用。
- 不改数据库格式或协议；保留撤销分组、中文组合输入、失焦／关页落盘与写败草稿。

### 第二批：库存、资源、界面

- 数量、位置、装备各有明确操作，只更新目标与真实依赖，保留物理物品 ID、授予归属和拖放状态。
- 扣费和恢复保留完整授权、账本及关联镜像校验；多来源、替换、撤回和上限变化有对应检查，不把局部更新误写成只改一格数。
- 组件按未变输入复用，订阅按卡／行／字段收窄。保住焦点、滚动、草稿、选择及隐藏卡，不通过改变 React key 强制重挂载修复显示。
- 不是禁止任何复制，而是禁止无关对象一起换身份。纯执行器、不可变快照与必要整卡派生计算继续保留。

### 第三批：首包、目录、缓存

- 按真实构建图拆分审阅证明与执行所需的最小核验数据，按机制／来源加载，避免只查身份集合也携带整份证明。
- 最小运行数据由同一核验输入可重复生成，完整性、真实性及未知版本守卫保持；不删证明或放宽散列来缩包。
- 当前卡先可读可操作，目录索引按版本复用。其他卡按需、可取消地准备；不能反复重新准备整批拖住当前动作。
- 仅依赖本地已就绪字段的操作不等待无关编辑库；需要规则上下文的控件按自身依赖等待并提示，不用未就绪数据执行，也不将整站锁住。
- 缓存命中复用解析结果，显式更新才换版本。Worker 和分帧要处理真实剩余重任务，不能把全量重复计算搬到空闲回调就叫优化。

### 第四批：持久化和同步

- 先测每次保存的角色数、字节数、复制、排队与确认，保留当前快照合并和恢复能力。
- 如果整本写入仍是瓶颈，再单列按卡存储／变更记录的迁移：兼容旧整本读取，内容与排序／活动卡分离，资源和回执保持一个事务，写败可恢复、旧备份可导出。验证前不替换现有格式。
- 远端仅发送实际变化文档与必要差异。提交时重核账号／房间、角色、写权限和版本；迟到、重复、乱序、撤权、断线、冲突不能抹掉新草稿或复活旧值。
- 独立版验收后迁移稳定行为及回归到枭熊。宿主授权、库存事务和消息约定仍分别适配，不能整包覆盖。

## 未来验收判据

| 检查 | 要证明的结果 |
|---|---|
| 纯文字 | 规则求值、三类同步、候选／目录索引重建均为零；未变选择和来源快照保持；只改必要显示／历史／保存 |
| 机制变更 | 同一相关协调不重复；处理明确拥有者与依赖，其他角色／条目不变；确需整卡派生计算时说明原因 |
| 实际体验 | 发布构建测输入响应、连续输入、保存、长任务及峰值；桌面／窄屏／输入法；同规模成对多轮，报告中位数、P95、最差长任务 |
| 资料与恢复 | 原生选择、手填数值、来源、未知字段、已花资源、库存、一次性领取和历史保持相应规则；保存／导入失败无部分写入，关页可恢复 |
| 权限同步 | 只读、另一编辑页、切卡、换账号／房间、撤权、重连、乱序／重复／迟到 ACK、冲突与恢复均走正常入口 |
| 加载缓存 | 冷／热／离线／损坏／显式更新分别测；当前卡不等无关卡或书，缓存不放行旧权限 |
| 完成口径 | 首次失败保留；共享核心用准确代码／数据回放及必要 CI；真机／独立多人未测就写未测；构建和计数不代替真实结果 |

毫秒门槛在固定机器、角色规模、发布构建的配对基线后确定。不照搬 FUS 的五秒／帧率，不承诺尚未测出的提速。

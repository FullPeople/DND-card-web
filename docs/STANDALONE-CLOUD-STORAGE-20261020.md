# 本机存储初始化与保留数据的恢复

范围仅为独立 `/cloud-lab/` 前端。正式站、枭熊、后台数据库和 QQ 会话不在发布范围。

## 原因与修复

原 `cloud/sync.ts`、`cloud/bindings.ts` 用 `openDB(name,1)` 直接读取，缺少初始化回调；若先于角色簿打开，会创建没有 `documents`／`cache` 存储区的版本 1 空库。后来角色簿同样打开版本 1，不再触发 upgrade，因此抛出 NotFoundError。两个“云端先开库”的定向用例在原实现均失败，修复后通过。这证明了一个实际代码缺陷，不能据此断言它是浏览器内一切存储异常的唯一原因。

所有角色簿、缓存及云端回执读写共用完整结构初始化。既有库按实际版本打开，仅添加缺失存储区；不删除、清空、替换既有存储区或记录。版本切换关闭旧连接，失败连接可重试。其他旧标签占用升级时给出可操作的错误，保留原记录。

如果旧库缺失的是角色正文区，结构修好后仍要求显式恢复备份，阻止新建空角色的自动保存。测试页提供从完整 JSON 恢复角色簿的入口：先验证全部角色，再用单一事务落盘；保留 ID、修订、数值、条目、填写内容及规则包；已有工作区则拒绝覆盖。普通“导入为新副本”的行为不变。

恢复后，玩家在本人已登录卡库重新选择原卡，才可恢复云端连接。核对账号与权限、既有待定回执和完整内容散列；个人内容不同即拒绝，不覆盖任何一端。标准备份包含站点共享来源视图，因此只在显示结果完全相同的情况下重建共享来源与角色原始来源的分离，保留站点设置及个人规则。已有冲突或未确认同步不能被恢复流程抹掉。

重建后的来源分离先持久化成功，再启用云端回执。保存失败或关闭页面不能留下指向尚未保存导出视图的同步绑定；等待保存期间的后续人物编辑保留。

- 22 项新回归通过：首次读取顺序、空壳修复、仅缺缓存、后续版本、并发开库、占用、失败重试、完整备份恢复、错误文件不落盘、已有工作区不覆盖、重新连接的账号／权限／内容与待定状态保护。
- 与保存、OAuth、权限、切卡、暂停配置一起运行，18 文件、171 项检查通过；类型检查通过。
- 私有诊断单独验证原页面导出的两张卡：完整解析后所有原字段逐项一致。与当前服务器原卡比较，只有站点共享来源字段不同；重建分离后原始内容散列相同，界面有效内容不变。私有文件不进入 Git 或发布包，这不是公网真人操作验收。

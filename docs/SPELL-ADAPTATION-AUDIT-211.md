# 当前法术字段适配核对 · 2026-09-28

针对用户询问“硬编码还是字段识别”，从本机既有资料快照调用当前求值函数，读取 33 个职业/版本/子职配置在 1、3、5、10、20 级的 165 个输出。此为实现审计，不是 165 项规则正确性测试，也不是全库支持声明。原始资料及逐级输出留在忽略目录 `local-rules/upstream-209/`、`work/spell-class-audit-211.json`；没有发布原始资料。

## 判定来源

| 内容 | 当前实现 |
| --- | --- |
| 职业/子职施法身份 | 读取 `casterProgression` 等施法字段；子职带施法进程时采用子职字段，等级仍用所属主职业等级 |
| 普通预备数量 | 优先 `preparedSpellsProgression[职业等级-1]`，否则解析 `preparedSpells` 算术公式；再合并人工调整 |
| 随等级选法数量 | `preparedSpellsChange=level` 或没有预备声明而有 `spellsKnownProgression` 时采用随等级选择模型；数量读其对应数组 |
| 戏法格 | `cantripProgression[职业等级-1]`，不含独立赠送 |
| 法师法术书 | 用 `spellsKnownProgressionFixed` 识别书本模型；只展示实际登记的有环法术，不自动把全表存入角色 |
| 全戏法候选 | 书本模型、`casterProgression=artificer` 或 `cantripChange=restLong`；这是当前能力推断，不是完整的特性许可系统 |
| 已知栏 | 书本模型，或有戏法数量的每日预备模型；没有施法职业时保留手填；显式手动覆盖和缺失字段的旧卡有回退 |
| 职业法表 | `_spellClasses` / `classes.fromClassList` / `fromClassListVariant`；匹配职业身份及来源；扩展书 PHB/XPHB 关联有显式兼容分支 |
| 攻击与 DC | `spellcastingAbility`；攻击=属性调整+熟练+人工调整，DC=8+属性调整+熟练+人工调整 |
| 法术位 | 单职业优先来源的 `rowsSpellProgression`；兼职使用代码内置的通用法术位表及施法进程折算；契约位也是代码内置算法 |
| 来源赠送 | `additionalSpells` 的 `known` / `prepared` / `innate`、等级门槛、明确法术 UID，以及 `daily` / `rest` / `will` / `ritual` 等 |

因此是“字段驱动 + 通用规则算法 + 能力推断”，没有按中文职业/特性名称编写分支，也不是所有行为都由数据完整声明。

## 仍然存在的边界

1. 全戏法列表由施法模型推断；显示候选不代表已经验证版本、等级、特性是否授予当前时机的替换许可。目前编辑时不执行长休/升级事件限制。
2. 法师升级抄录、免费学会若干法术、子职学派选择限制、职业特例没有完整选择与校验流程。部分起始施法门槛仍靠来源表而非独立规则协议。
3. 兼职普通预备数量按各职业求和，普通预备列表没有完整的逐职业归属/独立配额；戏法已有按职业的格子，攻击/DC 已按职业展示，不能据此宣称兼职选法已完整支持。
4. `known` 模型的数量主要生成空位，`learnActiveSpell` 尚未以此数量做严格上限校验。
5. 来源赠送明确 UID 和固定次数已支持；扩展法表、自选筛选、PB/属性动态次数、职业资源付费及完整长短休仍未全部接入。
6. 字段缺失时存在旧卡与手填回退、内置进程估算；未知第三方资料不能当作已自动适配。

# Tooltip 滚轮归属，本地候选

基线为 `ab68849`，运行代码与正式 305 的 `d4f8200` 相同。本轮仅提交隔离工作树候选，没有推送、合并或部署，也没有读取、导入或改写正式角色数据。

## 行为

说明正文或其中的横向表格仍有可滚范围时，先滚说明。短正文、顶部和底部把余下滚动量交给鼠标下方实际可见的阅读区域；不会依据最初链接的位置误滚另一栏。固定说明的透明遮罩也遵守这一规则。保留横向、斜向、Shift、行／页单位和 Ctrl 缩放手势。

下层内容继续遵守自身的滚动边界；明确模态框到边时不会穿透到背后页面，即使它没有额外的 CSS 滚动锁。多个固定说明之间也可依实际覆盖顺序承接滚动。

浏览器检查还复现了嵌套说明反复重建的问题：错误边界原先优先使用当前悬浮说明 ID，子说明出现时会重建已固定的父说明。现固定在第一张已固定说明，关闭整组后仍可重新打开和重试错误。

## 验证与证据

- 旧实现的真实浏览器失败仅在本地保留，其中 4 项失败。
- 首轮候选的 2 项失败分别暴露了测试跨多个说明的选择器及嵌套说明重建；随后单独保留的第二轮仍有 1 项嵌套失败，没有放宽超时或排除用例。
- 最终 Edge 浏览器 12 项全部通过：短／长正文、上下边界、标题、原链接、横向表格、模态框及无 CSS 锁的模态边界、独立下层栏、嵌套说明、透明遮罩和 Ctrl 手势。结果和三张已检查截图仅在本地保留。
- 4 项滚动单位、方向及边界单测、TypeScript 检查和差异空白检查通过。

这些浏览器流程使用实际 `KeywordPreview`、正文与样式，以及原创隔离夹具；它们验证网页事件和滚动容器，不代表玩家原卡、实体触摸设备或真实枭熊房间验收。没有运行全仓测试或发布检查。

接续紧凑提示后，专项服务器改用独立缓存与直接挂载夹具。组合重跑发现“没有 CSS 锁的模态框”用例有一次滚轮实际落在模态原生遮罩，立即读取零滚动的旧断言抢在浏览器滚动前通过；这不是 Tooltip 转发路径。现把模态框缩窄，使 Tooltip 实际伸出模态框，先验证指针命中 Tooltip，再分别核对模态内容边界和其外侧遮罩上的转发，均等绘制后检查背景不动。没有扩大为全局拦截非 Tooltip 模态事件。更严格的 12 项重新通过，证据与原组合失败均仅在本地保留。

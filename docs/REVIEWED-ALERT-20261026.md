# Reviewed PHB2014 Alert: bounded initiative ownership

This independent draft adds only an explicitly confirmed, source-owned initiative
component. It is not a new generic effect executor, combat system, or release.

## Player contract

- Select the genuine PHB2014 feat through a supported legacy class-ASI slot.
  Selection alone grants nothing. Review existing hand-entered initiative, then
  explicitly confirm that this component has not already been included.
- The fixed component is added to natural initiative, using final derived DEX
  and the existing 2014 Jack of All Trades calculation. Alert does not increase
  an ability or participate in ability-cap ordering.
- A retained manual final-initiative override still replaces the natural total.
  The existing card adjustment is then added. Confirmation never subtracts from,
  rewrites, or silently adopts manual values.
- Cancellation clears the draft. Replacement, clearing and reselection require
  fresh consent. Withdrawal removes only this confirmation, not the player's
  base values, manual fields, spent resources or unrelated grants.
- Source, level or automation suspension retains the same owned intent without
  applying its component. Missing, duplicate or recreated owners do not inherit
  consent. Retained unavailable records expose explicit withdrawal.

Surprise, consciousness, visibility, unseen-attacker adjudication and turn order
remain manual. The distinct XPHB origin feat keeps its previous behavior; its
proficiency and initiative-swap mechanics are not converted into the PHB bonus.

## Identity and compatibility

The adapter authenticates frozen mechanical-clause hashes, edition, pack and
source shape. Actual and canonical feat/class/ASI IDs all obey source restrictions.
Names and imported effects do not authorize this component or unrelated resource,
spell, training or ability grants. Publisher prose and input snapshots are not
bundled in the technical evidence.

The old `8e48bbbe801b21a57fbb9072b4d4c324379448ea` consumer can retain an unknown
intent without executing it. This is **not safe editing compatibility**: old
clear/reselect operations or manual edits may retain stale consent, and downgrade
can lose the original source instance. On a supporting client, withdraw, review
and reconfirm rather than repairing ownership automatically. Thin exports carry
totals, not new ownership; they cannot create a confirmation on import.

## Acceptance boundary

Directed regressions cover manual ownership, real catalog/source identities,
old-client retention and interrupted controls. Final acceptance additionally
requires a clean committed-source audit, the source-bound runtime replay and
paired report, exact-head CI, and actual desktop/narrow App persistence and
withdrawal flows. Static discovery or component rendering is not that acceptance.
Existing assertions, source locks and failure evidence remain in force.

This remains an independently stacked draft. It does not merge, deploy, alter a
server or claim compatibility with another owner's unrelated integration.

# Limited source uses — provisional implementation checkpoint

This new source checkpoint depends on the ordinary-casting development branch. It is not a final acceptance report or a release-ready comparison against main. Nothing is merged or deployed.

## First-pass mechanism

32 exact source entries have proven unconditional limited-use accounting. Each supports explicit genuine acquisition with a **known current balance, including zero**; no balance is prefilled or automatically granted at maximum. Source-owned spell payments cost the proven single use. History, resource mirrors, source/canonical identity, live edit/GM authority and locks are checked together. Duplicate/stale requests cannot spend again. Source pause, withdrawal, relearning, refresh, rest and native reopening do not refill the pool. Generic resource edits cannot bypass rule-owned history, while unrelated manual counters are not adopted.

The other 14 reviewed candidates are held, including timed/carrying conditions, weighted shared pools and ambiguous or alternative consumption. A confirmation cannot override those holds. Owner and generated child identities require their complete authenticated source snapshot and headers; coherent aliases retain canonical disable checks.

- All 32 admitted sources completed actual acquisition/payment/exhaustion/native workflows; all 14 held sources refused admission.
- Final focused core/source/guard tests: 73 passed, zero skips. Nine real-source SSR checks and TypeScript passed.
- An earlier adjacent aggregate passed 367 checks before the final narrow child-header closure; the focused tests above were rebound after that closure. Original semantic failures, fixture errors and contention timeouts are retained; timeouts and assertions were not relaxed.

This is an accounting mechanism, not whole-entry or spell-effect completion. Spell effects, action/casting time, targets, components, attack/save DC, duration and concentration remain manual except explicitly proven source fields; no class ability is inferred for these grants. No recovery is implemented. Older clients do not implement this ledger; safe old-client editing or round-tripping is not claimed. This is a local transactional contract, not server-authoritative proof of a campaign award.

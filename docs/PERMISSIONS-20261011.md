# 2026-10-11 · 云端 API 与网站端权限矩阵、本次修补

配套插件文档：obr-suite `docs/PERMISSIONS-20261011.md`（原生卡、怪物、中继与信任边界）。

## 身份与凭据（`server/cloud`）

| 凭据 | 来源 | 有效期 | 能做什么 |
| --- | --- | --- | --- |
| 网站会话 `dnd_cloud` Cookie | QQ Connect 授权码流程（state 一次性、绑定浏览器 nonce） | 30 天 | 全部账号操作；非 GET 需同源 + CSRF |
| 插件令牌 `Authorization: Bearer` | PKCE 配对（start → 网站授权 → poll），绑定来源 Origin 与网站会话 | 24 小时，网站退出即失效 | 读卡库、上传新卡、加载到房间、管理房间卡锁定与授权、管理编辑者；**不能删除云端原卡，不能迁移临时卡，不能用网站退出接口**（本次 `plugin_scope` / `cookie_required`） |
| 房间凭据 `X-Room-Capability` | 卡主把卡加载到房间时签发，存哈希 | 7 天；重新加载换新凭据、锁定状态不变 | 读该张房间卡；解锁期间可写 |
| 临时上传者 `dnd_temporary` Cookie | 仅 `temporary-ip` 模式 | 1 年 | 自己的临时卡；`account-private` 模式下无 CSRF、无法上传 |

QQ Connect 只提供 OpenID，`qq` 字段永远为空；按 QQ 号授权没有可信身份，本次起接口直接拒绝（`qq_grants_closed`），既有记录保留。

## 云端卡（账号卡）

| 操作 | 卡主 | 编辑者（账号 ID 授权） | 其他登录用户 | 未登录 |
| --- | --- | --- | --- | --- |
| 列表 / 读取 | 是 | 是 | 404 | 401 |
| 保存（PUT，修订号 CAS） | 是 | 是 | 404（本次，与 GET 一致） | 401 |
| 删除 | 是（插件令牌除外） | 403 `owner_only` | 404（本次） | 401 |
| 授权 / 撤销编辑者 | 是 | 403 | 404（本次） | 401 |
| 加载到房间、锁定、移出房间 | 是 | 403 | 404 | 401 |

房间卡写入：`write = 卡主 || 编辑者 || 未锁定`，正文到达后重新读取锁定与会话；卡主、编辑者的写入另需 CSRF；卡身份改变 422。

## 网站端（`src/`）如何对待这些权限

- 工作台（枭熊内）：宿主下发的访问目录（epoch、每张卡的 write/locked）是唯一依据；撤销时取消排队与在途写入、隔离本机草稿。**本次**：编辑标签页锁（另一标签页在编辑时本页只读）同样覆盖控制台、怪物页、背包等走宿主的变更。
- 单机云端卡：权限由服务端返回的 `role` 决定。**本次**：被撤销或属于其他账号的云端卡在本机也不能再改动内容（`edit`、`persist` 直接拒绝，生命值输入、快捷栏、撤销重做、后台自动同步一并拦住），自动同步不再对无权限的卡发起 PUT；本机副本仍可删除。
- 房间页（`?qqRoom=`）：只有服务端 `write` 为真时才能改动；**本次**：资源锁等 DM 类权限只给卡主，角色卡上的锁按钮在房间页禁用（房间锁由卡主在插件卡库管理）。
- 背包：GM 身份不再被当作编辑权，以宿主的 `container.write` 为准；控制台的生命条锁对云端卡隐藏（只有卡主能锁）。
- 配对：插件登录时显示 6 位校验码，`/library/?pluginAuth=1` 授权页显示同一校验码并说明插件能做什么、不能做什么。

## 服务端本次修补（`server/cloud`）

1. 插件令牌范围：不能 `DELETE /api/cards/<id>`、不能 claim、`/api/logout` 需网站 Cookie；`plugin/logout` 需插件令牌（原来各返回 500）。
2. 关闭按 QQ 号授权（400 `qq_grants_closed`）。
3. 对无权限者的变更一律 404，与读取一致，不再暴露卡是否存在；账号是否存在只对卡主可见。
4. 所有 CSRF 比较改为常量时间（`safeEqual`）。
5. 限流与配对/登录待处理上限按真实客户端 IP（nginx 的 `X-Real-IP`）计数，单个客户端不再能占满全局配额（每客户端 20 个待处理配对、20 个待处理登录）。
6. 磁盘保留 128 MiB 的检查覆盖账号卡保存、房间卡保存与临时卡迁移。
7. 过期房间凭据按访问清理；删除不可达分支。
8. 部署守卫 `deploy/qq/publish_backend.py`：拒绝用 `temporary-ip` 包覆盖已是 `account-private` 的后端；私有模式健康检查要求 `accountLibrariesPrivate`。

验证：`npm run test:cloud` 62 项（含本次 4 项）、`python3 -I -B deploy/qq/test_backend.py` 10 项、完整单测。服务端改动需按 `deploy/qq` 流程发布云端服务后生效。

## 已核对、保持不变

- 解锁期间任何持房间凭据者都可写，撤销编辑者只在锁定时立即生效：这是设计（房间成员协作），文档已写明。
- 服务端没有 DM 概念，`X-Role` 被忽略；"未授权 DM 只读"的保证来自这一点。
- `account-private` 模式下原上传浏览器仍可改自己的临时卡（但没有 CSRF，实际不可用）。
- 配对流程无法在服务端绑定发起方浏览器，校验码是用户侧核对手段。

# 单机角色卡逐功能性能审查

2026-11-07。**只审查和整理文档；未改功能代码、测试标准、存储格式或协议，未推送、合并或上线。** 依照 [短核心记忆](../AI_CONTEXT/CORE.md) 逐条追踪实际入口、变化对象、依赖与提交边界。

## 结论与版本

用户怀疑的核心情况确实存在：一些只改文字、位置或显示设置的操作，进入了整卡规则协调；深拷贝又让未变对象失去身份，触发第二轮协调和候选计算。库存、资源编辑器和词条编辑还有各自的重复工作。首屏负担另有静态依赖和整本角色准备两条路径。

**目前没有证据表明每次输入都会下载整个资料库、重算其他所有角色，或销毁整个网站。** 现有代码已经保留部分对象缓存、轻量编辑、虚拟列表、按卡云同步和卡面保留。这些应继续使用。

## 具体问题与修改范围

### S01　展示与布局没有完整声明编辑意图

**实测／最高优先。** 定位：`src/ui/App.tsx:783–808`，`src/ui/CharacterPages.tsx:33–35`，`src/core/displayCharacterEdit.ts:4`，`src/ui/Portrait.tsx:32–35`，`src/ui/FeaturePanel.tsx:107–118`，`src/ui/QuickbarManager.tsx:16–35`。

故事等普通回调复制整卡，初始化／水合，执行特性、法术、资源同步和全值比较；插画滚轮、特性折叠、快捷栏排序也能进入该路径。范围首先是当前卡，随后触发 S02／S03／S04／S16。方案是经验证的字段／操作声明，仅复制被改的小对象；纯显示、位置和机制变化分开路由。权限核对、修订、历史、落盘与同步仍须执行。不能靠任意回调标签猜它没有规则影响。

### S02　一次提交在多层重复协调

**实测＋代码确认／最高优先。** 定位：`src/ui/App.tsx:804,819–841,872–879`，`src/platform/cardViewReconciliation.ts:8–12`，`src/ui/SourceSpellControls.tsx:12,25`。

普通编辑已同步，未变嵌套对象因克隆换引用后，读取核对再复制、再同步。资源面板提交还有前后同步，来源选择控件也在普通回调内部同步。需要明确一次事务由谁协调，并复用绑定准确规则上下文的结果；先确认前后状态依赖，不能机械删除所有第二次调用。首次打开、旧卡恢复、版本变化的完整核对继续保留。

### S03　候选构造仍反复扫目录与已选内容

**调用次数实测、子路径代码确认／最高优先。** 定位：`src/core/automation/choices.ts:38–40,60–71,102–119`，`sourceClassChoices.ts:140–170`，`classSpellChoices.ts:12–24`，`sourceSpellPlan.ts:36–40`。

同一张卡的读取、特性协调和法术页分别构造选择；部分候选拼整库、逐项查找、按职业／选择类型再筛法术。`sourceClassChoices` 已在单次调用内延迟并复用派生计算，不能误称每个候选都重新 `evaluate`。应复用版本化目录索引、拥有者索引与机械输入下的候选；未展开选择按需构造。真实条件变更、已选的受限项、不同版本／来源身份必须正确失效并继续可见。

### S04　改一张卡仍重收集整本已选条目

**代码确认／中优先。** 定位：`src/ui/App.tsx:351–364`，`src/ui/useLibrary.ts:19–20`。

`workspace.characters` 换数组就平铺所有角色的选择，重建选中条目查找；整卡克隆还使当前卡的启用来源筛选、引用读取缓存失效。默认来源检查也因整个 workspace 改变而触发。应按未变角色复用分片，再更新目标分片；来源默认检查依赖真实来源状态。这里扫描整本不等于对整本执行全部规则；职业警告和管理行已有逐对象缓存，应保留。

### S05　库存预览与回写替换未改物品

**本次纯函数实测／高优先。** 定位：`src/core/inventory.ts:5–9,14–21,25–34`，`src/ui/InventoryPage.tsx:9–24`。

单机向预览传一个容器，预览深拷贝该状态；回写再生成全部物品选择。只移动一件，未移动的物品行和来源条目也换引用。添加一个不同物品时，50 件旧物品产生 100 次规范化 JSON 序列化，新物品身份重复计算。应只复制目标容器／行，复用其余条目；规范化指纹每个实际内容版本算一次。叠堆身份仍须包含来源、规则及其他有效字段，不能按同名或 ID 粗暴合并。保留数量、锁、修订冲突与显式删除语义。

### S06　库存网格按空位逐格查找物品

**代码确认、耗时待测／较低优先。** 定位：`src/ui/StockBoard.tsx:37–41,67`。

网格每个格子 `rows.find`，成本随格子数乘物品数增长；位置稀疏时空格也会渲染。可先按 slot 建一次索引，再评估大库存的可见区渲染。拖放开始／结束还有范围较广的 DOM 标记查询，应按实际拖放容器收窄。布局测量已有布局键依赖，不是每次鼠标移动都测全站；虚拟化前须验证落点、键盘操作、打印及状态物理效果。

### S07　资源面板小改动仍复制和比较整卡草稿

**代码确认／高优先。** 定位：`src/ui/ResourceDashboard.tsx:23–41`，`src/core/dashboardDraft.ts:10–40`，`src/ui/App.tsx:819–841`。

名称等设置每次变化复制完整 draft，再与初始整卡深比较；仅用于首次选择的模块列表表达式也每次渲染重算。打开时建立隔离草稿是合理的。应将面板配置草稿收窄、复用未变字段，初始化改为惰性；明确保存时再做必要验证。保留 base／live／draft 三方合并、并发扣费、受保护资源、锁、GM 权限、碰撞与实际持久确认。

### S08　拖一个资源模块就重建全部几何并两两碰撞

**代码确认／高优先。** 定位：`src/ui/ResourceWidgets.tsx:23–29,47–56`，`src/core/resourceWidgets.ts:198–216`。

每个指针事件重新构造模块和布局，碰撞检查逐对执行；此路径没有按帧合并。应复用稳定模块及邻居边界，活动模块与相关邻居比较，移动事件每帧只处理最新值；提交仍查真实冲突。现代布局保留邻居原位置，不能把它写成“所有模块都被重新排版”。指针预览本来就在局部 state，不能误称每帧都整卡保存。

### S09　法术页局部渲染仍重建候选与引用索引

**代码确认／高优先。** 定位：`src/ui/SpellsPage.tsx:75–93`，`src/ui/SourceSpellControls.tsx:16–25`。

法术页部分计算未复用共享选择快照；搜索来源法术时，每次按键重新合并全库并给全部法术建名称／来源索引，最后只显示一小批。应复用目录、角色机械快照及来源选择计划，搜索只筛当前候选。保留来源限定、同名歧义、旧受限选择和重复选择限制。控件内重复同步归 S02，不另算新问题。

### S10　渲染与来源校验重复携带完整正文

**代码确认，收益须分开测／高优先。** 定位：`src/ui/OrdinarySpellActions.tsx:12–16`，`src/core/automation/ordinarySpellCasting.ts:63`，`src/core/automation/itemChargeDebitSource.ts:14–22`。

施法控件每次渲染把当前选择的完整来源条目放入 JSON 基准；物品身份校验还有反复筛静态证明及正文摘要的路径。方案是静态证明按准确身份建索引、不可变读取快照复用内容摘要，呈现条件只依赖真实变化。**提交时的当前来源真实性与权限校验必须保留。** 不能仅凭 ID／显示名缓存，不能在可变核心对象上永久复用 WeakMap 结果，也不能用“不是物品”提前绕过错误类型伪装守卫。

### S11　词条编辑逐键生成隐藏 JSON 视图

**代码确认／高优先。** 定位：`src/ui/CustomEntryEditor.tsx:19,22,25,29–30,37–38`，`src/ui/CustomEntryCanvas.tsx:23,44,58`。

字段模式每次渲染解析 raw；改正文后重分段供画布使用，effect 再解析并序列化完整 JSON，同时设置另一份文本状态，虽然 JSON 页没有打开。可共享已解析结构，切换／复制 JSON 或保存时才生成需要的全文；大型正文预览独立测量后再按变化片段处理。无效草稿、原有列表／表格结构、模板撤回与完整保存校验必须保留。此阶段是编辑器局部负担，尚未修改角色卡。

### S12　保存词条／修改来源使共享上下文过宽失效

**代码确认／中优先。** 定位：`src/ui/App.tsx:844–861`，`src/ui/SourceSettings.tsx:18–20`。

单机词条保存即使 CUSTOM 已启用，也创建新的站点来源／启用来源集合；来源编辑还复制整张目标卡。应区分条目内容版本、目录索引和来源成员变化，成员不变时保留配置身份。真实来源开关需要影响依赖它的卡，不能只更新当前显示。停用保留选择并显示受限，恢复不补发资源；2014／2024 和来源身份分别保留。

### S13　首包和两个资料 Worker 携带较重静态数据

**公开包体与冷开实测／高优先。** 定位：`tools/startupChunks.ts`，`src/core/automation/itemChargeDebitSource.ts` 的静态导入，`src/data/catalogReader.ts`、`catalogReader.worker.ts`、`catalogNormalizer.ts`。

公开核心脚本解压后 7,481,358 字节；封签发布包中的两个资料 Worker 分别为 3,868,963、3,884,617 字节。这是不同产物的字节数，不能直接相加当首屏传输量。核心静态图中普通施法证明源码约 3.52 MB，仅取身份集合的模块也引入整份证明。应从相同核验输入生成最小执行元数据，按真实依赖拆分；完整审阅证明保留。Worker 不接收角色／账号数据，已经在线程内时不再套标准化 Worker，应保留这些边界。

### S14　目录发布等待整本角色准备，编辑可能使整批准备作废

**代码确认／高优先。** 定位：`src/ui/App.tsx:417–430,636–669`，`src/platform/standaloneCatalogPublication.ts`、`standaloneCardViews.ts`。

发布新目录前准备整本角色及引用索引；过程中角色数组变化可令准备上下文失效并重试。已有逐卡缓存和过期结果拒收，不能直接删。方案是当前卡先就绪，未变卡已完成结果继续复用，其余卡分批按需准备；上下文按真实版本及目标状态验证。还需按操作依赖解除无关编辑库的等待，规则未就绪的操作继续等待，不能带旧上下文执行。

### S15　就绪后连续预加载 19 类工具

**调用代码确认、是否竞争主线程待测／中优先。** 定位：`src/platform/warmTools.ts:4–24`，`src/platform/preloadQueue.ts:4–12`。

首次让步后，两条并发队列继续加载全部工具，也包括单机暂不需要的房间工具。应按使用场景和空闲预算逐批预加载，有输入或隐藏时推迟；保留点击即加载的可靠入口。不能把任何下载都归罪于这条队列，也不能未经测量断言它是 30 秒首开的主因。

### S16　本地修改按整本角色簿读写及备份

**代码确认／影响面广，迁移后置。** 定位：`src/platform/storage.ts:23–40`，`snapshotSaveQueue.ts`、`workspaceNavigationWriter.ts`。

保存事务读取旧整本、保留备份、写入新整本。40 ms 合并可以减少频次，不能避免每次真正写入的全量成本。先消除 S01／S02 的计算，再测保存字节和耗时；确有必要时单独设计按卡内容、目录元数据与版本化迁移。保留单事务、恢复副本、关页落盘、写败草稿及确认时机；普通切卡的导航元数据已有独立保存，不应改回整本重写。

### S17　第二只读标签页收到保存通知便整本读取和校验

**代码确认／迁移后置。** 定位：`src/platform/storage.ts` 的 `{saved:true}` 通知，`src/ui/App.tsx:577–587,629–635`。

只读页每次通知加载整本，再对全部角色 `readCharacter` 和初始化；写入页自身会跳过该重载。通知应携带变化角色／修订，在兼容旧通知和恢复逻辑下局部更新。不能取消浏览器单写入锁，不能把备份恢复／首次导入的全批校验也删掉。旧新标签页并存、漏通知和焦点恢复必须另有全量对账入口。

### S18　单卡回执事件重新读取所有卡的绑定和回执

**代码确认／迁移后置。** 定位：`src/cloud/CloudSave.tsx:92–109`，`src/cloud/sync.ts` 的回执事件，`saveScheduler.ts`。

事件已有角色 ID，监听端仍刷新所有角色状态；可按 ID 读取并合并，账号变化、权限定期复核和缺失事件继续完整对账。这是本地状态读取，不等于远端全量下载。现有远端按版本拉取、未变对象哈希缓存、按卡变更调度都应保留。不得减少会话校验、CAS、未知结果核对或授权有效期判断。

### S19　切换详细页会卸载并重建该页组件

**代码确认、是否值得保留更多面板待测／较低优先。** 定位：`src/ui/App.tsx:1199–1205`，`src/ui/RetainedCardSheet.tsx`。

不同详细页条件分支与 `ToolBoundary key={sheetPage}` 会重挂载当前详细页，其局部计算／滚动状态可能重做。角色卡保留层已能保留最多 4 张卡，不是全站销毁重建。先测切页与草稿影响，再决定保留轻量状态还是面板；不能为了减少重挂载同时保活所有重面板、扩大移动端内存。撤权时清掉对应不可访问内容是必要行为。

### S20　数值解释面板逐次预览复制整卡

**代码确认、成本待测／较低优先。** 定位：`src/ui/ValueTrace.tsx:50–56`。

仅解释面板打开时，预览草稿值会复制整卡并求值。预览确需重新算相关数值，但可只复制目标修正字段并复用未变条目。普通 `NumberInput` 已保留输入草稿和中文组合输入保护；不要为优化解释面板破坏这些行为。

### S21　特定状态物理效果对局部子树变化重新收集全部格子

**代码确认、成本待测／较低优先。** 定位：`src/ui/useCardGravity.ts:8–81`。

仅对应状态效果启用时，子树 childList 变化触发当前卡根下格子收集，再判断身份是否真的变化。格子集合未变不会重建全部物理体；普通状态已提前返回。可先检查 MutationRecord 与受影响格子，保留原效果、最大运行时限、减弱动态偏好和隐藏卡暂停。未在真实移动设备测量，不能称它是通用卡顿根因。

## 已有保护与必须保留的全量工作

- **玩家资料：** 来源快照、选择、运行次数、布局各有归属；未知字段和手填内容保留。停用不删除，恢复不重领；物品来源不同不能按同名叠堆。未变对象复用与内容不丢失必须同时证明。
- **可靠保存：** 队列只有实际持久化后才结算成功；整本备份和内容在一个事务内。首次导入、损坏恢复、明确版本迁移可以全批验证，须离开逐键路径；不能删检查或备份来显得快。
- **冲突与资源：** 历史和面板保存继续三方合并。移动物品不能覆盖期间变化的数量；改颜色不能恢复已花次数。法术位、来源次数、物品充能和回执按各自真实事务一起提交。
- **权限与同步：** 本地单写入锁、账号／房间／角色切换、即时写权限、请求版本和迟到回调守卫保留。独立版 `sendCharacter` 不发送枭熊消息；账号云存档有自己的按卡调度，不能混同宿主同步。
- **已有有效优化：** `runtimeCharacterEdit` 的明确运行字段分叉、`displayCharacterEdit` 的已覆盖字段、目录完整快照缓存、引用索引、虚拟列表、逐卡快照缓存、卡面保留、触控帧合并继续使用。缓存可证明内容未变，不能证明仍有权限。
- **显式完整操作：** 复制整卡、用户选择导出多页、导入整批验证、完整规则上下文切换、账号全量权限对账均有合理全量范围。优化目标是减少无关依赖和重复，不是禁止所有循环、哈希、复制或渲染。

## 权限和同步的确定规则

将操作分成三类：个人查看偏好（浏览版本、文字显示、个人界面主题），角色内容（数值、选择、角色版本、卡片颜色），房间配置（DM 管理的规则与扩展）。个人查看偏好不要求原卡写权限；角色和房间配置分别验证其权属。

只读卡仍可浏览、查看云端信息和导出。未授权 DM 没有绕过卡主权限的入口。房间编辑者拥有卡主给予的内容编辑权限；授权管理仍按卡主权限执行。卡片颜色属于原卡数据，不能为了让调色按钮可点而解除原卡保护。

云端卡继续使用原生五页角色卡，名字后的云图标、登录后的云按钮和 QQ 二级弹窗保持一致。单机二级弹窗继续支持导入当前场景。房间修改自动写回云端原卡，网站、卡库及房间副本按修订号收敛；测试必须覆盖非当前卡、未打开的卡、账号切换和授权撤回。旧版仅移植与其现有结构适配的功能，不自动迁移玩家档案。

离线编辑保留本机待同步记录；重连时先核对远端修订。存在真实双端冲突时保留草稿并说明冲突，不用无条件覆盖来制造“全同步”。结果不明的写入以 requestId 核对；删除成功回执与撤权先到的竞态纳入回归，不能重复删除或无限等待。

## 按依赖执行的七个阶段

1. **测出真实基线。** 恢复浏览器控制，确认当前账号与实际安装入口；从一张测试卡和单个窗口开始，记录点击到反馈、读取、运算、保存及跨端可见的时间。采集 Chrome 主线程、请求耗时和服务器资源，不扰动真实原卡。产物：复现步骤、时间线、截图和热点清单。
2. **先恢复权限与会话正确性。** 优先解决虚假编辑锁、浏览筛选误当改卡、QQ 状态迟到、账号切换和撤权竞态。先在克隆测试卡上验证，再进行两端与两人房间验证。产物：权限矩阵、单窗／双窗／崩溃恢复结果；这一阶段可独立发布止损修复。
3. **处理共有的耗时路径。** 根据时间线消除重复会话读取、重复资料解析／规则计算、全卡册序列化、长同步队列和过量预取；拆分大任务，取消过期读取，共享已在进行的同类请求。保留即时本机反馈、顺序保存和服务端授权检查；避免每次按键启动一次完整远端流程。产物：相同数据与设备的前后对照。
4. **修复首开与具体界面。** 对首次页签采用受预算限制的空闲预热或框架反馈；完成所有选中态、插件配色、权限原因、云端弹窗及原对象拖影。按桌面、390 px 窄屏、A4 与已有非 A4 偏好核对。产物：九项逐条截图／录像与交互结果。
5. **测出容量和故障边界。** 逐级扩大测试卡数、卡片复杂度、房间人数及连接数，区分客户端、SDK、中继、数据库和线路限制。仅在前一级资源和延迟都安全时扩大；达到限制即给出可用规模、推荐规模及降级方式。产物：容量曲线和可运行的最低测试环境说明。
6. **分别发布并实际验收。** 五个目标按依赖分批发布，后端需要时先部署兼容版本，再部署客户端；每个目标有新恢复点、最终源码检查和公网产物核对。回退按该批实际依赖决定，不使用固定的历史顺序。至少两个独立真实房间成员完成账号、卡主／非卡主／未授权 DM、骰子、双向编辑、断线恢复和 30 分钟使用验收。
7. **通过后加动效并收尾。** 只为已合格的交互加入轻量动效，复测帧时间、响应和内存；达不到预算的动效移除。最终报告说明每项结果、边界、回退点和未解决事项，关闭测试窗口与进程，结束本轮工作。

阶段不会因时间或预算用完而自动标记通过。一个阶段连续两轮没有显著收益时，先复查原始时间线和测量方法，再改变方案；外部服务或设备限制需给出证据及替代办法。真实浏览器依赖未恢复时，可继续源码与服务器工作，但阶段 1、6 的实际验收保持未完成。

## 性能验收预算

以下是待实现的验收目标，不是对现状的描述。先核实设备条件；标准桌面测试条件暂定为现代浏览器、至少 4 核／8 GB 内存、10 Mbps 以上网络、往返延迟不超过 150 ms。真实用户设备和线路另外采样，不能套用标准环境结果。正常档暂定 30 张混合卡、两位独立房间成员；实际常用规模超过它时，以实际规模追加必测档。

P95 表示 95% 的样本不超过预算。每个主要交互至少采集 30 次，原始数据、样本数量、失败率、最长一次都保留；成功样本快而部分操作超时不能算通过。

| 操作与计时边界 | 标准环境目标 |
| --- | --- |
| 点击到可见反馈，包括设置／公告／开关／编辑 | P95 ≤ 100 ms；不等网络才按下或显示加载状态 |
| 已加载的弹窗、Wiki 条目及页签切换完成 | P95 ≤ 250 ms |
| 首次角色页签或弹窗，从点击到可用内容 | P95 ≤ 1 s；立即保留框架，避免空白 |
| 热缓存可用工作界面 | P95 ≤ 2 s；未读资料独立加载 |
| 冷启动可用工作界面 | P95 ≤ 5 s；标准网络；QQ 扫码的人为等待另计 |
| 已登录的 QQ 弹窗和目录 | 热读取 P95 ≤ 1 s，首读取 P95 ≤ 2 s；后台核验不冻结其它控件 |
| QQ 回调确认到按钮、权限与卡库可用 | P95 ≤ 1 s；从本应用收到回调开始计时 |
| 角色本机编辑反馈／保存 | 反馈 P95 ≤ 100 ms，本机持久化 P95 ≤ 300 ms |
| 简单编辑至服务器确认／其它在线端显示 | P95 ≤ 1 s／2 s；同时记录抖动与失败，不用删除冲突检查换速度 |
| 骰子点击反馈／热启动可见演出 | P95 ≤ 100 ms／250 ms；冷 3D 资源准备目标 ≤ 2 s，独立记录 |
| 掷骰到真实第二成员收到权威结果 | P95 ≤ 1 s；保留 3D 默认、暗骰权限、历史和个人 2D 偏好 |

云端当前的 5 秒轮询天然可能超过 2 秒跨端目标，需要评估安全的变更通知与回退策略。只通知摘要和修订，正文按需读取，限制重连和失效重试频率；是否新增通道由实测结果决定，不预设一张卡一个长连接。

如某项预算被第三方 SDK 或 QQ 服务限制，记录可控制部分与外部等待，提供实际可达到的数据及产品降级行为。预算调整必须在报告中明确理由，不能静默降低后宣布完全通过。

## 如何找到上限和下限

卡片数依次试 1、10、30、100、300；每级包含空白卡、典型复杂卡和头像／长法术列表卡。资料库使用真实公开资料量；卡库分别测摘要分页、当前及相邻预览和完整文档读取，不把所有卡都同时挂载。先测用户现有规模，再扩大合成副本。

大卡量采用本机测试数据或隔离目录／后端夹具；生产仅核对已有数据及少量可恢复测试卡，不在用户账号批量创建压测卡或更改账号产品策略。

房间从 1 人、2 人起步，4 人、8 人在有可用测试成员时测；合成 SDK 不能冒充真实参与者。服务器连接数上限用隔离负载回放逐级探索，生产只做有资源门限的小规模验证。未测到的规模明确写未测，不由两个浏览器推算几十人可用。

网络分别测正常、150／300 ms 延迟、1 Mbps、短断线、长期离线；设备测当前电脑，之后用受限 CPU／内存配置定位低端敏感性。受控限速和 CPU 限速仅是模拟条件，真实手机或另一台低端电脑结果单独列出。

每个目标交付三条结论：**最低已通过条件**（设备、网络和卡量）、**推荐日常规模**（仍有延迟和内存余量）、**首次不通过的条件**（哪项指标超预算、是否提供可用降级）。在既定探测范围内始终通过时，只报告“已验证到该规模”，不声称找到了绝对上限。

## 服务器和电脑的资源纪律

服务器没有理由承担前端构建；在本机 U 盘工作路径构建并上传审查后的包。继续保留中继的 96 MiB 老生代、4 MiB 半空间、16 MiB 队列、256 MiB 服务上限，以及管理与维护任务已有的内存限制；先测热点，再讨论其它服务的合理上限。

性能采样期间每 5 秒记录可用内存、服务内存、Swap、连接数、队列和重启计数。限制日志长度与正文采集；采样不记录原卡、昵称目录、会话 Cookie、QQ 令牌或密钥。资源记录在浏览器断开后仍能独立核对。

停止扩大压力的初始门限：可用内存连续 3 次低于 256 MiB，或单次低于 128 MiB；Swap 相比该级基线增加超过 128 MiB；任一服务接近已有限额的 85%；出现新的 OOM、自动重启、显著 5xx 或数据库锁等待。触发时停止施压并保留证据，恢复健康后才能继续较低档位；不通过增大内存上限掩盖泄漏。

30 分钟典型使用与至少 100 次打开／关闭／切换后，要求无新增 OOM、自动重启和持续 Swap 增长；浏览器与服务内存记录增长趋势。每轮闭合操作后的稳定窗口若连续上涨，必须定位；不用一次峰值或一次垃圾回收后的下降证明没有泄漏。

初始服务器观察条件为保持至少 256 MiB 可用内存及既有限额余量，实测后给出适合当前 1.6 GiB 服务器的日常预算。压测门限不是硬件容量保证。

测试原始日志和截图合计控制在 1 GiB 内，单次跟踪控制在 100 MiB 内；工作树和依赖单独核算，尽量复用已验证依赖与规则快照。禁止循环下载相同源码包或为每次样式修改创建完整测试包／回退包。发布时每个目标仍须新的可恢复备份；清理前核对在用版本、最近恢复链和数据库，确认站外归档可恢复后才处理历史包。

## 发布与最终收尾线

每批发布需记录准确 Web／Suite／后台源码及依赖。Suite 明确绑定本轮 Web 工作树，不使用混合旧根目录。真实资料覆盖守卫和最终提交的 CI 继续执行；触及相关运行模块时完成项目要求的完整回放，不用旧提交成功替代新合并树验收。

授权范围包括单机网站、角色卡库、新旧枭熊插件及其相关服务器服务。首页、三龙牌、玩家数据库和既有旧浏览器存档导出入口继续保护；旧插件不会因优化而被强制迁移。正式切换前重读线上基线，漂移则重新核对，不能覆盖其它会话的新版本。

全部满足以下条件才结束目标：

- 九项反馈有最终结果、对应截图／耗时／权限检查，不能用“已加代码”替代验收。
- 五个目标分别完成常用规模验收，客户端与服务器容量结论附设备、网络及样本数。
- 只读浏览、卡主编辑、授权编辑、未授权 DM、切账号、登出、双窗、刷新、崩溃、断线恢复和冲突保护通过。
- 同一张云端测试卡在网站、卡库和真实房间两端收敛；非当前卡、名字和绑定目录更新通过；旧版适用路径单独验收。
- 上述主要性能预算通过，或外部硬限制已有明确证据与可用方案；任何未达成项都保留为未完成，不能宣称彻底优化成功。
- 真实 QQ 登录及至少两位独立真实房间成员验收完成，30 分钟连续使用和资源观察通过。
- 发布后的实际文件与受测来源一致，每个已改目标有新恢复点，原卡数据与非本轮应用检查通过。
- 若加入动效，默认使用 100–180 ms 的 transform／opacity 过渡，输入立即响应、避免布局抖动，支持减少动态效果；加入后不超过原性能预算。
- 最终报告列出原始数据位置、改善前后结果、已验证上下限、源码与回退点；停止测试进程、关闭新建测试页、处理合成测试卡并保留恢复证据。

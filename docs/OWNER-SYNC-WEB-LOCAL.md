# 原生 Owner 同步与首载恢复：Web 本地验证

日期：2026-10-03。基于已发布 240 的 main `112e3d0`，在隔离分支 `fix/obr-owner-sync-20261003` 修改；保留同分支 DM 权限入口提交 `d3412f4`。本记录只描述 Web 修复，不代表发布或真实房间验收。

## 已复现的原因与修复

- 角色/资源/生命值保存使用捕获的旧卡或排队回调，发送前没有统一核对当前写权限。80 ms 合批以及已发请求后的队列能跨越撤权→重授继续写。现按逻辑目标保存授权代次，撤权、宿主/作用域改变、断线与 BFCache 恢复失效旧意图；重授只允许新的编辑。角色撤销/重做也在修改本地工作区前检查当前权限。
- 宿主可能将快速撤权→重授合并为仍然 `write:true` 的目录。读取每个 CacheGrant 的 `grantVersion` 字符串，在目标版本改变时失效旧意图；其他目标的无关变更不取消当前目标。请求携带 `accessEpoch/accessScope/accessRoom`，由配套宿主核对该历史授权快照与实际原生 Owner。Web 不读取历史 `owner_ids` 或自定义 metadata 来创造写权限。
- 同 epoch 的旧缓存消息可替换授权目录；ACK/预热快照曾可重新确认断线前权限。现同 epoch 目录不可变，回执只更新允许范围内的数据，不能授予权限或结束权限悬置。无 access 目录的兼容宿主也处理明确撤权，并保留当前权限合并 ACK 中的目录。
- 原生撤权后背包容器旧 `write:true` 可延续到完整目录到达。现用当前授权约束背包显示及发送。传输/历史记录保留所有涉及目标用于取消；已经撤权后发起撤销，不再发送历史请求。仍保留公共仓库及目的地接收的既有语义。
- 已发写入被撤权时发送 cancel，明确标记其结果仍可能不确定，继续查询原回执，不重放。暂时断线只失效未发意图，已发请求保持回执等待。撤权和 ACK 在同一 relay 批次到达时，等待恢复处理后再派发终态，避免队列被错误永久阻塞。
- 首次 `navigate(itemId)` 会清空 target 并显示加载中，但随后该目标的预热快照只入缓存，不能完成等待视图。现只有最新明确目标的有效预热文档能结束加载；旧 A 快照/选择回复不能抢回新 B。等待期间对 hello 做退避重试，不重发 select、不改变地图跟随；合法空选择不猜测第一张卡，撤权/完成结束等待，后台标签不做额外加载重试。

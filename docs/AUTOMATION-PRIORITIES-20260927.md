# 自动化优先级 · 2026-09-27

本文件记录用户本轮优先级，不代表已实施或已上线。自动化原型仍封存在 `U:/code/DND-card-automation-dev`，只做本机验收；不能整体合并其旧 193 基线或恢复当时被撤回的界面实验。以已发布 207 为后续迁移基线。

## P0：保存与显示可信，是所有自动化的前提

- 先修角色文件往返丢失武器攻击；同一份已记录的攻击供卡面和枭熊显示，不要求重复装备。
- 卡片、服务器、棋子状态不一致，以及上一笔保存未确认的问题仍待实际房间诊断。不得清空保护队列来伪装修复。
- 基础值、派生结果、已消耗资源分别保存；重算、切卡、重新导入不能重复加值或恢复次数。旧卡保持手动模式，迁移提供副本和差异，不改写原卡。

## 第一批：用户明确最重要的四项

### 1. 护甲与盾牌，一起完成

装备护甲后，以护甲适用的 AC 计算方案替代默认未着甲方案，不把两套基础 AC 相加。切换护甲只保留一个生效的穿戴槽；卸下恢复适用方案。盾牌是独立装备槽和加值，不作为另一件护甲；两面普通盾牌不重复加值。

轻甲、中甲、重甲的敏捷规则分开；无甲防御、法师护甲等作为带条件的候选方案，不能同时叠加。盾牌与某个方案是否兼容必须看结构化规则，不能按中文职业名字写特判。2014/2024 分开处理训练要求；2024 未受盾牌训练时不自动获得其 AC 加值。人工绝对覆盖与卡面加减修正保留，展示完整依据。

验收：敏捷 16、无其他效果时，未着甲 13；皮甲 14；鳞甲 16；链甲 16；具备对应训练且使用普通盾牌后分别 16/18/18；卸盾只减盾牌贡献，卸甲恢复适用基础。覆盖负敏捷、同调、魔法加值、两件护甲替换、双盾、无甲方案不兼容盾牌和两个版本。

原型已有护甲/盾牌用例，可复用纯计算部分，但不能据此称线上已具备自动装备计算。

### 2. 装备武器 → 可直接掷骰的快捷攻击

装备后自动生成攻击行，显示命中、伤害、伤害类型和使用属性；卸下撤掉自动生成行，背包物品和手工攻击仍保留。更换力量/敏捷、熟练、等级或魔法加值时更新。

分别表达近战、远程、投掷和单手/双手多用模式；投掷不能笼统使用敏捷，多用伤害不能变成额外伤害相加。只有真实适用的熟练加值进入命中，不重复加入伤害。特殊职业属性替代来自规则数据；不支持时显示待人工核对，允许手工填公式。

快捷栏只引用装备来源，不复制发放物品。手工公式不被自动模式覆盖；每行标记来源身份与生成方式，导出后完整恢复。点击命中和伤害分别使用可见公式。

验收：装备/卸下、属性改变、熟练改变、投掷与多用切换、同名不同来源、手工攻击并存、导入旧卡、网站 → 新旧枭熊 → 网站往返；页面文字与实际掷骰请求一致。

### 3. 职业、子职、种族授予的固定法术

随来源和来源等级添加，使用与普通自选法术不同的灰色双线框或来源角标；保持原 A4 风格。不允许拖动、拖出删除、占用普通可更换槽或点击取消预备；仍能查看正文和施法。移除授予来源时只撤掉该来源实例，玩家自行学习的同名法术保留。

必须区分：始终预备/额外已知、有限次数免法术位施放、随意施放、允许再用法术位施放、仅扩展可选法表。不能把它们统称为无限免费施法。多人兼职分别保留施法属性、DC、攻击值、职业等级和来源。数据声明选择时由玩家选择，不自动挑选法术。

复用现有特殊法术和次数资源框，补来源自动关联及不可拖动行为。重载、升级、切换来源不恢复已消耗次数；休息时才按声明恢复。

验收：两个职业同名法术但不同属性、一个法术两个来源、删除其中一个来源、自带法术不占常规容量、升级后出现/降级后暂停、仅扩表不自动学会、一次免费使用后可否用槽、刷新不恢复次数、规则禁用保留选择并显示受限。

## 第二批：常驻加值和资源操作

装备/同调带来的属性、豁免、技能、速度、生命上限和法术加值；可追溯来源与堆叠规则。然后做施法位/次数消耗、长短休恢复、撤销重做及保存失败恢复。生命上限变化不等于自动治疗；资源扣减是明确操作，不放进每次渲染的求值器。

## 第三批：临时效果和战斗裁决

祝福等临时效果、上下文骰子、游戏时间到期；随后才考虑目标、专注、命中/伤害/抗性裁决与回合规则。未知规则明确待人工处理，不用“已自动化”掩盖未支持部分。

## 每批交付门槛

每次只做一个可体验闭环，先本机、再审阅后接入枭熊。沿用原型的纯规则核心，分别验证导入、保存失败、快速切换、多标签页、刷新与真实点击/拖拽。构建通过不替代浏览器验证；真实房间和实体手机未测写待验证。五页卡面、人工修正和现有手动模式必须保留。

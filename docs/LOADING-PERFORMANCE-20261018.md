# 2026-10-18 · 首页、角色卡和 Wiki 加载优化

本轮在隔离副本完成候选修复，计划统一发布网站／卡库／Wiki 301、新插件 301-dev 和稳定插件 1.3.34；实际发布以最终回执为准。网站以远端 `307056e68d4fcbb0788278043dfc56941d8d10ed` 为起点，原有混合工作区保留。首页完整源码已纳入 `site/homepage`，复用原切图、项目图片、React Bits 组件与骰子资产，并从本轮实际线上脚本恢复当前项目说明及下载地址。

## 已复现的原因

1. 首页一次导航实际请求了 `index-cloud295-d49aba624eb2.js` 和 `index-BK9-n3kZ.js` 两份入口。浏览器记录为 `playing → complete → playing → complete`，最后一次初始化把侧栏重置为关闭。不能只改构建后的入口文件名，却留下动态资源对原入口的引用。
2. 角色卡退出动画同时等待 `ready`、动画完成和样式完成；程序或样式变慢时，动画停在最后一帧。现在将退出动画与可操作状态分开：动画照常淡出；实际内容及样式未就绪时显示真实读取状态，保持卡片不可操作。不会提前宣布完成，也不会显示未排版的卡片。
3. Wiki 返回的 HTML 原本只有空容器；界面未挂载时空白，资料未到达时又先显示“没有符合条件的条目”。现在由 HTML 提供真实启动状态，内容与样式均就绪后才展示首个真实视图。错误与重试独立保留。
4. 部分角色页通过临时加载面板替换现有卡片；阅读器切换资料时先清空正文。现在准备目标期间保留已显示内容；书籍标题、正文和章节在新内容就绪后一起切换。
5. 原首页以 `1000 px × 540 px` 判断默认展开范围，将常见平板归为收起。现在默认展开包含 600／768 像素平板；手机竖屏及常见横屏继续收起，并校验真实触摸与指针特征。

## 实现范围

- 首屏保留原开屏素材及编排；首页原图先完成解码再播放，退出有独立时限。首屏不加载骰子引擎、物理 worker 或 WASM。
- 首页在电脑和平板开屏期间准备侧栏代码及真实图片；图片未完成时保留上一完整轮播帧，不绘制灰色占位图。移除按固定 180 ms 猜测 WebGL 是否启动成功的判断。
- 首页恢复入口文件失败时的重载操作，避免永久停留在开屏背景。
- 角色卡保留保存、编辑、五页、公告顺序和故障恢复；准备好 Wiki 程序后提前复用，规则资料索引相互独立下载，减少串行等待。
- Wiki 同时等待实际内容与样式，保留显式失败、重试和资料异常说明。加载期间不显示假的空结果；分类切换不再先使用上个分类的类型筛选。
- 修复仪表盘新增资源并保存后，旧表单误报未保存修改的问题。原反馈的删除法术位、新增资源、编辑子项、保存布局和重开流程均另做浏览器检查。
- Suite 普通投骰、先攻及群体结果文字在五秒后自动清理，清理不再依赖视口请求成功。手动打开的历史仍由用户关闭。
- 透明浮层分别提供原生窗口和普通嵌入入口，在首次绘制前确定画布配色；两种入口共享原始资源图。合成像素检查覆盖系统深浅偏好及默认、浅色、明确深色的外层。
- 保留 QQ／云端暂停、现有项目及下载入口。未改后端、线上服务、玩家资料和旧站。稳定插件保留原配套查看器。

## 验证与边界

针对本轮源码的规则、状态机、缓存、传输、阅读与原开屏素材重点检查通过 86 项；Suite 67 组回归、17 项文字演出浏览器流程通过。首页七种布局／故障场景和实际延迟加载投骰通过，首次打开没有请求物理引擎，点击后投掷完成。新插件 224 项、稳定插件 24 项实际构建浮层的合成像素通过；设置与配置背景另作不透明对照。最终生产构建、完整单元与浏览器结果以统一发布记录为准。

本机三个界面均另做了真实规则源测试，包含手机条件 `1.6 Mbps`、`100 ms` 延迟和 4 倍 CPU 降速。示例：手机首页约 3.2 秒结束开屏，Wiki 约 4.0 秒出现真实条目；这些是本机受控样本，不是公网或全部设备的速度保证。首屏背景和读取状态的绘制时间不能当作“角色卡已可操作”或“资料已可阅读”的时间。

规则运行报告需按新消费者重新生成，不手工替换散列，不跳过原始 229 份资料与 18,789 个身份的门禁。完整 CI、正式发布、实体手机／平板及玩家原线路不因此视为完成。

本轮另核对三个旧来源专项的当前公开输入。装备 AC 专项原先拒绝了比锁多 9 字节的文件；重新逐项核对六个原身份、版次、类型、基础 AC 与页码后，29 项带真实源检查通过。只更新已独立验证的输入大小／散列与日期，原机械投影、缺失规则范围和历史来源记录保留；下载工具仍严格拒绝下一次漂移。战俑和盾牌来源采用同样的逐项复核，未调整断言或发布上游原始正文。

本地证据位于隔离副本 `.local-evidence/loading/`：

- `public-baseline.json`、`public-home-graph.json`：本轮实际线上时序与重复入口证据。
- `candidate-metrics.json`：电脑、手机、平板的真实源样本，区分状态、真实条目和绘制时刻。
- `runtime-audit.log`、`runtime-audit-final.log`、`browser-results.json` 及各组构建／测试日志：两轮完整规则回放与本轮验收。
- `screenshots/`：电脑、平板、手机截图；截图和上游缓存不进入公开仓库。

## 本地预览

先构建单机卡片、独立 Wiki 及 `site/homepage`，再在 Web 副本运行 `node tools/serveLoadingPreview.mjs`。默认入口为 `http://127.0.0.1:5320/`，角色卡 `/card/`，Wiki `/wiki/`。首页源码可通过 `DND_HOME_ROOT` 指定。原骰子素材目录可通过 `DND_HOME_PUBLIC` 指定。

预览服务器只监听本机，提供压缩和实际资源缓存；角色修改保存在本机预览域名的浏览器存储中。这里只读取公开项目点赞，写入请求不会转发至线上。

## 最终检查中补修的加载时序

首次显示卡面时，资源操作可能早于延后下载的编辑功能。现在保留这次操作，功能就绪后按顺序执行，并重新检查角色身份、当前目标和写入权限；加载期间换卡或失去权限不修改其他角色。已通过首次操作、权限撤回、换卡和连续消费／恢复的针对性浏览器检查，生产包仍须完成完整来源守卫与最终 CI。

并行资料索引在持续断线时收集所有已启动请求的错误，再暂停后续队列，恢复时不会遗漏必要索引。离线缓存按实际使用的功能收齐其静态依赖后才登记入口，避免已缓存入口却漏掉依赖文件。安装初始应用壳与后续预取分别验证；没有扩大为安装时下载所有工具。

首页轮播开场改按实际经过时间推进，慢帧率不再把既定开场延长。卡面在淡出下方先完成真实绘制，但直到可操作才进入无障碍树，避免刚显示时吞掉输入。切页检查以目标页签真正选中作为后续操作起点；保留首次实体按压、样式、持久化和断线恢复断言。上述改动后的最终规则回放、完整检查与实际部署结果，以最终发布记录为准。

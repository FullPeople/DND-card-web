# 角色卡与卡库的发布范围

dnd.center 的首页和其他子站由不同项目维护。角色卡发布包只能包含 `card/` 和 `library/`；清单必须明确给出 `targets: ["card", "library"]`，同时包含两个入口。不能把构建时的默认首页打入实际发布包。

发布器保留站点根目录及其他路径，分别原子切换两个目标目录。完整检查当前基线和受保护服务，在切换前备份两个目标；任一切换或就绪检查失败时只恢复本次已经切换的目标。第三方同步更新的首页或新目录保留，不能用旧整站备份覆盖。

回滚只恢复两个目标，并保留后续首页、三龙牌及其他子站的文件。SQLite 始终使用现有持久目录，回滚前端不恢复旧数据库。其他受保护配置、服务或角色卡自身发生漂移时，应停止并核对实际状态。

所有站点发布使用共同的 `/run/lock/obr-static-release.lock`；同时核对其他项目的实际发布锁和回执。构建包、Git 提交或上传到服务器均不代表已经完成上线。先读取 Nginx 当前配置及成功回执，再封印最新基线。

旧整站发布包绑定自己的冻结发布器，不能把新版脚本复制进去后继续按旧封印运行。恢复旧首页应定向恢复其入口和资源；不能为此回退原来的域名 410 配置。

适用验证包含 Linux 真实目录原子切换、第二个目标失败后的恢复、数据库新增记录、第三方首页和三龙牌更新、根目录身份保持，以及拒绝范围外的首页文件。应用运行代码没有随本次发布器修复改变；应用与发布器各自记录其受测提交和构建证据。

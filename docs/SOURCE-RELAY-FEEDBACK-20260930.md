## 部分房间 401 的已证实原因

只读核对线上服务与该会话的 Nginx 状态码，没有读取角色正文或写入房间。服务自 2026-09-27 启动，重启次数 0。报错会话先正常工作，之后有 29 次宿主注册 503、300 次宿主 429，并伴随客户端 292 次 GET 401；读取时窗口内约 98 个不同宿主会话有成功请求。

旧服务最多 100 会话；容量满仍先增加每 IP 每小时注册计数。每 1.4 秒重试会把一次容量不足放大成整小时的注册限流。客户端还可持续刷新闲置会话存活时间，拖延宿主已离开的会话释放。宿主未注册成功时客户端 401 是结果，不能通过关闭鉴权解决。

本地修复：

- 会话默认上限改为可配置的 512；保留每 IP 成功创建限流。容量拒绝不消耗额度，返回具体错误及 Retry-After。
- 按宿主活动时间清理过期会话，客户端轮询不能续命；不驱逐仍活跃的宿主。
- 增加全局 64 MiB 排队消息预算，保留原有单队列条数与体积限制、认证、宿主权限及文档并发校验。
- 宿主请求先等唯一注册流程；Web/Suite 两端尊重 Retry-After、指数退避并提供会话失效提示，不每 1.4 秒无限刷 401。不会自动重放保存或库存修改。

上线需要 Web 客户端、Suite 宿主前端和中继服务同批处理；只发布角色卡静态文件无法修复旧服务器容量逻辑。此候选没有改线上服务或重启进程，真实房间恢复仍待上线后验证。

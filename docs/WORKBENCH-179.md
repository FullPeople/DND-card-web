## 界面与行为

- 总览与角色卡的资源按内容收窄、左侧流式换行；总览名称增大。总览卡片沿用厚描边切角框，背景与边框同一几何；状态泡在名字旁，可拖入、移出和转交。物理效果限制在卡内，倒地翻转名字。
- 物品右键打开操作菜单。“转移至…”使用二层菜单，只列玩家资源中实际出现的单位；放入公共仓库保持独立操作。
- 法术页取消法术位区；宽屏法术格五列、14 px 高。左键或自制拖拽预备／取消预备，右键菜单，悬停维持 Wiki／提示预览；预备区与下方法术池不重复显示。根据来源结构推导学习制、法术书和职业全法表，并保留编辑模式手动覆盖。详见 [SPELLS-179.md](SPELLS-179.md)。
- 修复术士的狂野魔法／龙族血脉子职版本归属；按主职业身份及父级来源匹配，保留两个核心版本的独立身份。
- 背景属性加值只作说明，不加到实际属性，也不改属性区排版。2014／2024 基础版本只约束 PHB／DMG 家族，其他扩展按启用来源通用。
- 鸣谢字幕提速并增加同时出现数量；最新绑定棋子图片作为没有自定义头像时的默认头像，使用 URL 引用，不塞入角色文档，独立立绘不受影响。
- 补齐场景中血量和状态提示，修复通知 iframe 生命周期、首帧确认及点击穿透。资源、背包、转移、法术准备提示继续使用同一通知体系。
- 修复骰子记录关闭及真实鼠标拖动；包含源 iframe 松手、预览延后打开、快速拖动后松手的竞态。
- 总览／投骰旁新增仅 DM 可见的 BBCode 笔记。持久保存采用修订号校验，切换面板不丢草稿，迟到回执不覆盖新输入，失去保存回执时读回核对。

## 笔记隐私与边界

笔记不放进玩家可读的房间 metadata。宿主检查 GM 身份后使用随机不可猜测的私有文档地址；凭据保存在当前浏览器，未广播给玩家。同一浏览器的同一 DM 可刷新恢复；另一浏览器／设备不会自动得到这一私有笔记地址。本轮未实现笔记跨设备迁移。

跨卡状态转交沿用两张卡各自的权威数据，属于顺序写入。确定失败时作字段级补偿；结果未知时保留诊断，不回退整卡，不把已提交内容误判为失败。

## 当前卡远端刷新修复

已经复现两条缓存问题：全房间串行 hydration 被另一张慢卡拖住；旧 GET 在远端新通知到来后完成，重新写入新鲜时间并吞掉失效。前端接到完整的新 selection 时可在原卡上正常刷新，因此修复重点在宿主缓存与调度。

所有角色文档成功保存后立即发布只含角色 ID／修订号的失效通知，不再等待棋子投影和场景通知；补齐数值及状态专用命令此前漏发的通知。文档读取按卡独立处理，当前卡优先、后台并发两张；旧请求被新失效主动取消并补读，重复修订直接跳过。真实 SDK 双宿主探针中，另一张慢卡或本卡旧 HTTP 响应仍挂起时，当前卡分别在 9.2 / 5.9 ms 收到新文档。20 次重复通知只有 1 次补读，40 次未变场景事件没有新 GET。同连接旧格式通知仍能刷新；真实保存命令尚待棋子投影确认时，另一端在 9.2 ms 已更新。这是本机应用调度测试，不代表公网实际延迟。

保存并非每次发送整张角色卡：现有协议按变化分支发送并合并，头像等未变化对象不会随普通数值更新回传。数组仍作为一个变化分支，例如状态与特性共用的 selections；本轮不将其仓促改为易受排序影响的数组下标更新。首次读取及发生变化后的文档读取仍为完整文档，使用条件请求缓存。

# 正式单机版 QQ 登录与私人卡库接入

用户授权：接入已验证功能、保留样式与角色数据，完成备份及测试后部署；枭熊不部署，测试数据不得覆盖正式库，注意服务器内存。

## 边界与实现

- 基于已通过本人实卡验收的测试版源代码，另建独立工作树。正式版使用显式的单机与卡库构建配置，原浏览器数据库、设置键、正式 API／Cookie 不改名；普通与枭熊构建仍暂停云端。
- 现有正式后台进程读取原数据库 `/var/lib/dnd-card-cloud/cards.sqlite`（实际为 `/var/lib/private/dnd-card-cloud/cards.sqlite`）。不导入、替换或合并测试数据库，不触碰测试版与枭熊静态目录。
- 正式后台仅开放既有账号／私人卡片 API。插件凭据、枭熊来源、连接和房间接口保持暂停，账号通知不得附带房间范围。仍按账号隔离目录、按权限读取和写入，核验 CSRF 与修订冲突。
- 用户本机草稿、已有绑定、未知写入和冲突保护沿用实卡验证版；恢复时先持久化再启用核验过的云端绑定。角色切换复用快照、单独保存选择，数值修改合并后台保存。
- 保留原定时备份程序与服务、计时器。正式后台复用原 service 和 StateDirectory，仅新增明确的启动及资源上限配置：Node 堆 192 MiB，MemoryHigh 256 MiB，MemoryMax 384 MiB，CPUQuota 50%，TasksMax 32。

## 发布检查

服务器首次只读检查：总内存约 1.6 GiB、可用约 560 MiB，磁盘剩余约 2.9 GiB。全部构建在本机／CI 完成，服务器只接收排除数据库、备份、私有导出与测试目录的成品。发布时再次检查内存至少 384 MiB 与备份空间；散列按 1 MiB 流读取，SQLite 备份按页进行。

原正式库 141 张卡、212 个账号，SQLite quick_check 正常；测试库独立，同样为 141 张卡。正式浏览器原有一张本机卡，已经由正式页面导出并解析完整 JSON；该备份忽略于 Git，不进入发布包。测试版两张本机卡不向正式页面导入。

发布程序先验证冻结包、工具散列、当前 main 及同一提交的完整 CI，建立本次独立 card／library／后台与正式 SQLite 备份。候选先在正式备份的独立临时副本验证兼容性，不写原库；再切换后台代码与资源上限，核对所有既有数据表逐行散列、数据库 inode，最后原子切换两个前端目录并保留旧散列资源。故障回退程序和目录，不用旧数据库覆盖部署期间可能已保存的新记录。

保护项包括正式网站其他目录、枭熊 suite／suite-dev 全树、Nginx、原数据库备份脚本与任务、测试库内容和测试后台进程。超时只查回执／持久标记，不重复发起发布。

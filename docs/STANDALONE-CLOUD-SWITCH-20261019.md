# 单机云端角色标签切换

用户已用真实 QQ 在 Chrome 和 Codex 内置浏览器登录，并确认本人私人卡库很快显示。随后明确指出：卡顿来自角色卡上方的角色标签相互切换，尤其切回已打开的云端卡。本轮只处理独立云端测试入口；正式单机定稿和枭熊端不发布。

## 改动范围

- 已打开角色的来源投影、构建视图、可选项、迁移检查和派生数值，按不可变快照复用。缓存属于当前编辑器；规则目录、规则包、来源或房间上下文改变时重新建立。新编辑快照重新计算。普通暂停构建和枭熊路径不启用此缓存。
- 单纯切卡在首次内容持久化后，只写当前角色 ID。角色内容、头像和完整备份不再随每次切卡重写；内容修改继续使用完整快照事务。刷新从独立元数据恢复选中项，完整内容保存原子清除旧元数据。仍等待真实事务完成才显示保存成功，失败保留原失败状态。
- 已检查过的同一份角色快照，不因来回切换重复启动云端摘要和同步。首次查看和实际编辑仍检查，切离前的待存修改继续保存；权限、CSRF、修订冲突及不确定写入恢复不变。
- 顶部角色标签记录点击至布局提交、后续绘制帧的耗时，只写无身份信息的 DOM 属性，便于区分页面真实耗时与浏览器控制工具耗时。外观、触屏拖动和键盘切换保留。
- 同时保留上一轮本地 QQ 登录反馈：先显示保留档案／连接提示，记录准备耗时，并在用户准备点击时连接 QQ 域名。不能据此宣称偶发授权页长等待已修复。

## 验证记录

类型检查通过。16 个文件、147 项相关检查通过；新增独立工作量检查另行通过。覆盖真实 IndexedDB 选择恢复、内容与备份保留、失败重试、保存调度、账号隔离、冲突和不确定写入保护。

两张各带 200 条原创内容的角色，在相同真实计算函数下进行 20 次 A–B–A 切换。旧路径构建、选项、审阅和派生各运行 22 次；候选各运行 2 次，均为首次打开。重复计算部分约 322.16 ms 与 0.79 ms。此为 Node 计算对照，不是整页、玩家设备或公网响应时间。两个输入快照前后完全一致。

涉及受审计的 App 和存储模块，需使用原始 229 份输入重新执行全部 18,789 条规则回放，不能仅更新指纹或沿用旧观察结果。全量回放、正常构建和实际页面计时继续记录于未提交 `.local-evidence/cloud-stage2/`。

## 更新边界

独立测试前端更新器仅接收 card／library 静态文件。持有发布锁，复核现有入口散列，生成新回退副本，保留旧散列资源，通过原子目录交换更新。测试数据库不替换，后台不重启，既有 QQ 会话保留；正式网站、正式 SQLite、Nginx 和后台文件需保持一致。更新器不调用首次安装器，不再次复制账号或人物数据。

实际页面与更新回执待补。毫秒级目标以点击到绘制的实测为准，不将纯计算缓存命中解释为所有设备上固定 1 ms。

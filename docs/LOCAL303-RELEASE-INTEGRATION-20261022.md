## 验证和发布门槛

应用不变时保留此前完整本地回归、实际导出、保存恢复及同卡册性能对照证据。改动过的发布工具运行既有测试及实际正式构建。整合后的最终提交仍需完整远端 Web、生产配置、云端迁移和 Linux 发布契约检查，不能仅引用整合前的结果。

浏览器回归发现三处配色用例仍要求正文内层为不透明实色，与已验收的透明度修复冲突。只更新 `palette257.spec.ts`、`palette258.spec.ts` 和 `ux259.spec.ts` 的实际着色层和颜色预期：外层必须保留指定颜色的 66% 不透明度、正文内层透明。长按预览不写入、释放只写一次、撤回／重做、取消、配色导入／导出、刷新、独立自定义副本及人物数值保留检查继续执行，原时限不变。应用源码不改，原失败和后续最终结果分别保留。

改查真实外层后，长按预览用例又暴露了取色时序：在背景过渡动画中捕获到中间色，再与最终保存色严格比较会失败。只补等待该着色层实际动画结束，继续严格核对最终预览色、保存色、取消恢复和单次写入；不改动画、产品逻辑或原时限，失败日志保留。

同轮法术用例仍查找已删除的隐藏“已预备／已选”文字；该隐藏文字正是已验收 PDF 重叠问题的来源。`spells-179.spec.ts` 和 `spellWorkspace210.spec.ts` 改为同时验证原有 `aria-pressed` 选中状态、实际可见的勾号及其读屏隐藏属性，取消后勾号必须移除；预备栏、拖放、右键、刷新、窄屏和全屏流程继续执行。没有把失败用例删除或改成跳过，也没有为了测试恢复导致 PDF 重叠的旧文字。

另两处首轮失败保留完整上下文：公告的加载占位和真实内容共用名称，原测量可能在替换期间得到空几何；仪表盘原用例在异步保存结束前就点关闭，保存保护拒绝关闭后遮住后续控件。`announcement.spec.ts` 先等真实 FAQ 与可用确认按钮，原高度／滚动断言不变；`standalone183.spec.ts` 先等“已保存布局”与保存按钮禁用，再关闭并确认弹窗消失。产品的保存保护、界面实现和原测试时限均不改。

# 网页架构与下一阶段

代码分为三条独立的数据线：`src/data` 接收中文站原始资料并建立稳定身份；`src/core` 保存角色的选择、资料快照和纯函数计算；`src/platform` 负责浏览器存储、文件交换与离线网页。React 只负责显示和操作。

条目身份包含来源、类型、原文名称及职业/子职/等级上下文。中文同名不代表同一条目。2014 与 2024 分开筛选；兼容旧版内容需要角色主动开启。中文站更新只更新右侧目录，不重写左侧已选快照。

规则求值不执行 JSON 中的脚本，也不修改当前生命值或资源计数。职业和等级产生填写要求；拖入的选择关联到要求。来源、前置位置或等级改变后，失效内容留在文档中并暂停效果。撤销恢复文档，不重放“授予资源”行为。

人工修正具有数值目标、最终值和原因。它覆盖计算结果，随完整角色、审卡与枭熊导出说明保留。这样可以在规则适配不完整时继续使用角色卡，同时让 DM 看见依据。

浏览器工作区使用 IndexedDB 保存当前版本及前一次备份；同一页面内串行提交，支持 Web Locks 的浏览器只允许一个标签页编辑。目录缓存、工作区及网页静态文件分别管理。程序更新等待用户保存后切换；资料更新另行进行。

## C++ 边界

下一阶段可以使用 Win32/WebView2 承载构建后的网页。优先替换 `src/platform/storage.ts` 的异步存取与文件接口，核心规则和界面继续复用。暂不建立第二套 C++ UI，也不把规则引擎移入原生层。

音频板与桌面骰子中值得继承的是：明确的 UTF-8 边界、原子导入、失败时保留原数据、可恢复保存和实际窗口验收。网页测试通过不代表未来原生宿主的输入、文件权限或生命周期已验证。

## 后续规则系统

首版规则包只支持白名单声明式操作和选择。已有 Godot `@` / `effect` 触发栈并未冒充已移植。后续可把事件、条件、资源消耗与效果栈独立成带版本的执行协议，并用相同输入/输出夹具同时验证网页和游戏运行时。先保持行为可追溯，再扩展指令集。

# B/C 优先的性能目标 · 2026-10-15

用户本轮第一目标：暂停 A 的排查范围，先让枭熊 B 与网页 C 加载和同步流畅；覆盖人物五页、生命值、状态、资源、法术位、背包、公共仓库、怪物、快捷栏、播报和投骰等功能。单机版同样优化。Wiki 在本地复用，重新打开和页面切换不重复处理完整资料库。云端 A 排在之后。

## 已核实的 295 数据路径

- QQ 云端入口、目录和后台活动已暂停。
- 普通角色完整文档仍通过 obr.dnd.center/characters/<room>/<card>/data.json 读取，通过原中继 CAS/delta 保存。暂停 QQ 不等于普通角色已完全由 metadata 持久化。
- 棋子 metadata 包含运行值、绑定和投影基线，不是每张普通角色完整文档的唯一存储。
- 背包事务、公共资料和部分怪物覆盖仍有服务端共享文档路径。
- 角色五页共享一份 Character 状态，但各页代码原先首次导航才加载。
- Wiki 原先缓存原始 JSON，每次打开仍遍历和归一化这些资料。

## 本轮独立实现

在保留 295 暂停开关和保存协议的前提下：

1. Wiki 成功完整加载后，额外保留带解析版本、资料源作用域和来源名称的归一化视图。后续默认开启直接读取此视图，跳过逐份原始 JSON 遍历和 Worker 解析。显式更新或失败文件重试仍走原有恢复流程。
2. 不完整、失败、暂停或中止的刷新不能替换完整缓存；缓存不可用不使已加载资料失效；解析版本和资料源变化重新构建。
3. 首屏揭开后自动并发预加载人物各页及常用编辑工具，无需先切到该页。只下载模块，不挂载隐形编辑器或执行业务操作。保留首屏与编辑运行时的分层，不预热 3D 骰子或 QQ 入口。
4. 对单机与集成生产构建分别验证页面预热、重复切页、Wiki 重开零上游请求和零解析 Worker。受控浏览器不代表真实四端验收。

这一步不把人物持久化搬到 metadata，也不宣称普通房间已经完全脱离服务器。

## 后续 B/C 改造底线

- 逐域明确权威：人物完整定义、运行值、背包事务、布局、Wiki、一次性演出不能共用一个模糊的保存成功条件。
- 从 metadata 观察到实际变化时立即更新获准读取的同一份本地视图；不能等待切卡、切页、全库下载或无关功能队列。
- 写入不能在页面、血条和播报间悄悄分叉；保留本机 metadata 与适用血条完成条件。拒绝、未知结果和待同步分别表达。
- 减少整文档下载和整场景回读。公开增量只带对应域的必要变化；权限撤回立即移除缓存；无权限的整卡不能公开广播。
- 选择 metadata 作为完整持久层前，先验证并发更新、容量、重复绑定、转场、没有在线玩家、权限、备份及恢复；不能用最后写入整卡覆盖并发编辑。
- Wiki 与人物快照分离；资料更新不修改人物已选快照、不补满已消费资源。

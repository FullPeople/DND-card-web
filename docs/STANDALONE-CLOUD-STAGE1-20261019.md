# 单机云端重接 · 第一阶段，仅本地

用户要求分阶段重新研究 QQ 登录和云端卡库，先做单机，枭熊后置。本阶段完成旧链路审查、单机云端保存调度优化，以及独立本机账号的实际读写试验；没有恢复公网云端，没有真实 QQ OAuth 验收，没有改动枭熊端。

隔离工作副本为 `cloud-stage1/web`，从已发布 302 的文档提交 `31ba56f` 建立。原单机定稿工作副本、5317 预览、5353 内嵌预览和现有角色资料未参与本轮修改。普通 `availability.ts` 仍为 `false`，只有显式使用本地试验配置时才编译启用；不是使用浏览器参数或旧偏好打开公网功能。

## 已确认的工作量来源

旧 `CloudSaveProvider` 在角色数组变化 650 ms 后，遍历所有本机角色的绑定并逐一调用同步引擎。每张已绑定卡都会读取并对完整内容排序、序列化、哈希；改一张卡也会产生全卡册工作量。该步骤不等同于每张卡都上传，但仍可能占用主线程。角色中较大的图片字符串也进入原有摘要。

已认证账号有变更通知，同时 Provider 仍每 5 秒重新读取会话、绑定和目录。QQ 选择器弹窗另有自己的刷新路径。这些是源码及受控对照已确认的风险，不能据此断言历史真实卡顿全部由它们造成，也不能先认定是枭熊的问题。

## 本阶段改动

- 单机现有账号控件登记当前角色，冷启动先检查当前卡；连续编辑合并后只处理对象实际变化的卡。快速切卡不会丢掉原卡已经排队的修改，排序不会被当作编辑。
- 对 App 提供的不可变角色快照，用 WeakMap 复用内容摘要；新对象重新计算，失败摘要可重试。缓存不按角色 ID 或本地修订号复用，也不缓存授权。该约定只适用于不可变快照，不能拿它包装会在原对象上修改字段的调用者。
- 隐藏、断网和只读期间暂停新的自动工作，恢复后继续处理队列。同步引擎仍先等本机保存完成，再使用原有账号核对、CSRF、版本比较、冲突和不确定结果保护。
- Provider 的周期读取改为 60 秒恢复检查，正常变更使用既有账号通知。QQ 弹窗和独立卡库的其他轮询尚未在这一阶段整体重写。
- 没有改动角色格式、规则实现、现有样式和 `App.tsx`。70 个受审计模块逐字节核对一致，使用原来源报告通过正常构建门禁；没有更换摘要或跳过门禁。

## 验证结果

12 个相关测试文件、122 项检查通过，包括新的调度／快照工作量测试，以及原有真实 HTTP、SQLite、账号隔离、CSRF、版本冲突、不确定写入恢复、保存等待和暂停边界检查。类型检查通过；普通暂停版与独立启用试验版都按正常生产构建通过。未将定向测试称为整个项目或真实 QQ 全量验收。

可复现工作量对照使用 40 张原创角色，每张带 250,000 字符内容，连续修改同一张卡 8 次。使用相同的同步引擎与摘要函数，旧路径进行 328 次摘要计算，候选进行 9 次（含当前卡初次检查），角色快照读取分别为 328 次和 17 次，两边都写入 8 次，最终生命值均为 8。这里的快照读取是本机读取，不是 HTTP 正文下载；用例未测量公网延迟。运行耗时随并发测试负载变化，主要比较可重复的工作次数，不对所有玩家承诺固定倍数。

实际浏览器在独立的 `http://127.0.0.1:5361/`，使用本机测试账号与新建 SQLite 数据库：

1. 由页面按钮进入测试账号，在原账号弹窗导入“云端读写测试卡”。
2. 当前生命 20 → 17、临时生命 2 → 5，两次连续修改合为一次实际 HTTP PUT。
3. 测试药水 2/3 → 1/3，保存后立即切到另一张本机测试卡；原卡仍完成第二次 PUT。
4. 切回并刷新后，角色名、17/30、临时生命 5、药水 1/3 均保留。直接只读核对独立数据库修订 3，原备注、能力值和其他资源字段保留。
5. 刷新及闲置期间没有额外 PUT。两次本机 HTTP PUT 分别约 11.66 ms 和 26.99 ms，不能解释为公网或真实 QQ 保存耗时。页面本轮未捕获 error 级控制台日志。

构建时一次通过 App 传递当前 ID 的尝试触发了来源指纹门禁。该改动已完全撤回，改由现有云端控件登记当前卡；最终 70 个模块均未变。工作量测试最初没有等待真实摘要 Promise 完成，出现计数不足；修正测试等待后重新通过，原失败日志保留。没有把这些失败称为通过。

证据位于未提交的 `.local-evidence/`，实际文件存于 `U:/CodexWork/2026-10-19/standalone-cloud-stage1-evidence`：最终测试日志、普通／试验构建日志、`cloud-stage1/workload.json`、`persisted-roundtrip.json`、`http-metrics.json` 和 `browser-roundtrip.png`。测试数据库与会话不进入公共源码。

## 使用与下一阶段

预览：`http://127.0.0.1:5361/`。这是本机测试账号，不能输入真实 QQ 凭据。5361/5362 均只监听 loopback；启动器会创建新数据库和新会话，重启后旧试验记录仍在证据目录，浏览器需要重新从试验首页进入。现有真实账号和云端卡没有迁移到这里。

本地启动命令：`node tools/cloudStageOnePreview.mjs`。只用于第一阶段；正常构建和公开入口继续关闭云端。该工具不与任何正式数据库、QQ 凭据或部署配置连接。

下一阶段先接单机的真实 QQ 登录与私人卡目录，保持点击后才启动、目录只读摘要、当前卡按需读取，并验证登录退出和账号切换。之后再做两端同时编辑、断网／弱网／重试和大头像主线程分析，最后考虑枭熊宿主。当前结果支持继续推进，不代表真实 QQ、真实公网或整个旧卡顿问题已经解决。

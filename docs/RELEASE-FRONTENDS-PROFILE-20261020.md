# 正式前端发布入口修正候选

本候选基于已合并首批 `7d45da5e051d1a459e77f7fffe79336868e0644b`。首批只包含 2024 属性提升、导出合拢与恢复、钱币显示；属性生成、重复技能提醒、祈唤和怪物库各自保持独立范围。本候选没有服务器上传、预检封包写入或页面切换。

## 已复现的问题

现有正式发布工作流调用 `npm run build:cloud`，该脚本取默认单机／卡库配置。按当前已核验的 1.0.303 正式基线，这些默认配置继续暂停云端功能，不能作为正式 QQ／私人卡库更新输入。

在隔离工作区完整执行旧构建后，两份待发布目录均缺少 `cloud-profile.json`。用真实 Edge 打开编译后的卡库，页面显示“云端功能已暂停”。浏览器只使用原创匿名 API 夹具，不连接玩家账号；这证明构建入口错误，不冒充真实 QQ 登录验收。

## 修改

新增 `npm run build:production-frontends`，只构建 `vite.standalone-cloud.config.ts --mode standalone` 和 `vite.library-cloud.config.ts --mode standalone`，通过正式配置核验后，将两份产物放入 `dist-cloud/card`、`dist-cloud/library`。正式发布工作流改用此入口。原默认、内嵌与旧云构建保持原有暂停边界。

检查器同时核对直接构建和实际待打包目录：启用云端、私人卡库、原存储命名空间、正式 API 路径、无枭熊模块及无测试命名空间。Python 打包器在私人卡库模式下还会独立拒绝缺少或关闭正式配置的包，拒绝发生在生成发布目录和改写版本标记之前，不能把默认暂停包仅靠元信息标成正式包。

原有封包／完整源码归档检查移入可跨平台运行的测试模块，原断言全部保留，并新增缺失配置、暂停配置拒绝和正式私人包通过的真实封包检查。完整 Linux 发布契约仍由原有 CI 执行，没有模拟 `fcntl` 或放宽平台检查。没有修改服务器发布器、SSH、OIDC、权限、凭据或人工审批。

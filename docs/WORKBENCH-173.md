# Full Suite-dev 1.0.173 · 背包、公共资源与拖拽权限

## 本轮行为

- Wiki 所有类型均可拿起拖拽。背景、种族、职业、子职、法术、训练等在普通模式落到纸卡时提示「添加「条目名」前，请先在角色卡右上角开启编辑模式」，不写入；物品、状态仍可直接使用。点击缺项只定位 Wiki，不自动开启编辑模式。
- 背包和公共仓库采用紧凑切角格，四角分别为名称、数量、价值、重量。拖拽保持格子原样和抓取偏移，放下对齐落点；单击数量进入输入，Shift 拖拽或 Alt 点击拆分，右键仍可部分转移。
- 装备、同调为不限数量的引用区，原物品仍在背包内，分别显示装备标记与同调发光。两种标记不自动改变角色计算。
- 负重上限按已选择体型和有效力量计算；编辑模式可填算式，如 `*2+10`、`(基础+30)/2`。算式只接受有限算术，不执行脚本。
- 公共仓库默认 4×5，仅网格，可重排；资源计数独立在下方，不挤占物品格。玩家可调整未锁公共计数，设置由 DM 管理。
- 总览角色/怪物切换只列出当前场景有绑定棋子的资料，固定三列。生命、临时生命、盾牌 AC、锁定、被动察觉与资源分别排列。资源支持无上限数值、锁定、悬停设置、进度条点击输入；预设可拖入，同名时询问覆盖或共存。公共预设与角色预设分开。
- 「DM不提示消息」替代偷窃模式文字；锁定角色对无权限玩家隐藏总览字段，资源提示隐藏具体内容。
- 本地卡片编辑、资源、库存转移/拆分/排列/引用和公共计数纳入撤销重做；同步库存先显示本地结果，确认只合并，不重新播放新增动画。库存错误提供复制诊断。
- 魅力内容缩紧后完整容纳，背包和物品格继续参与纸卡框体特效与碰撞。

## 追加修复的实际原因

同一状态在 Wiki 叫「束缚」，场景定义可能叫「束缚 🔗」。旧 hydration 按完整显示名比较，替换了选择行 ID；随后宿主又给原始行补 `_suiteStatusId`，导致撤销删除与实际存储内容不等而误报冲突。现按归一化名称保留已有行 ID，宿主不向原始行发明 UI 注释，真正的并发内容修改仍拒绝覆盖。

连续保存按角色串行。只有确实排在本地写入之后的批次使用该写入确认，不拿很久以前的确认覆盖新的观察快照；不同角色各自保存观察文档。生命值撤销使用当前操作的前值进行冲突比较，不复用旧角色标签的数值；未修改数字时失焦不新增历史记录。待保存计数覆盖编辑与撤销，旧确认不会提前清除后续操作的脏标记。异步撤销期间的新编辑也不会被错误弹出历史栈。

法术空白未在新浏览器复现：真实上游的 2014/2024 文件均有法术，本轮加载得到 608 个可见条目。已加强无效索引缓存恢复与核心法术文件回退，保留加载失败/重试；不能据此断言原用户浏览器的筛选或缓存具体是哪一种原因。

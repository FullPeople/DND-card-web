## 玩家操作与改动

| 操作 | 本批处理 | 保留的边界 |
|---|---|---|
| 姓名、人物资料、背景故事等十五栏 | 沿前批明确的展示意图，只更新对应字段；复用未变规则、选择和数值读取结果 | 普通回调、未知字段和真正的规则变更仍走规则路径；撤销使用当前权限及三方冲突检查 |
| 移动物品格位 | 明确的位置操作单独提交，保留物品快照、数量、余额及资源；拒绝旧位置、重复目标和已移走物品 | 缺少旧背包设置的首次初始化仍执行正常路径；不能凭历史 key 猜测安全 |
| 添加、数量、拆分和转移 | 库存预览按变更复制；未变行、来源快照及其他容器复用；堆叠比较只为新行计算一次身份 | 数量、装备和来源仍进行必要的机制协调。完整库存快照继续代表实际持有，缺行不代表主动放弃赠礼 |
| 一般机制修改后的核对 | 完成的编辑事务向当前卡及后台共用的上下文记录完成，减少无变化的第二次核对 | 后台预热不是事务提交；旧卡、远端新快照、目录或来源变化仍独立检查。权限不进入缓存 |
| 法术页、自定义条目输入 | 主页和导出复用同一次读取已有的准备状态，避免每个法术重新求值整卡；法术读模型复用相同的不可变角色与目录；未打开 JSON 输入时不逐字重建完整 JSON | 当前余额和提交资格继续读取；切换输入方式、原始结构、无效草稿、示例撤回及保存需实测 |
| 外部导入 | JSON、批量、Excel 入口沿用实际导入核对机制，标记填写已核对并隐藏待填提示和已忽略选项；已有明确核对标记可直接识别 | 不伪造答案、熟练或资源，不把核对标记算规则完成；保留显式调整入口、未知条件提示及以后升级的新选项 |

未修改保存／同步协议、数据库格式或授权判断。没有增加模型调用、API Key 或网站 AI 助手。独立版稳定后再对齐枭熊，本批不发布插件、Wiki 或后台。

## 失败、纠正与验收边界

1. 原库存历史用例否决了“把完整快照当局部快照、保留缺失物资”的首版设想。恢复完整持有语义，保留原测试。格位也是完整投影，不能保留会与实际格子冲突的孤立位置；未知外层资料仍保留。
2. 最初的完成标记只挡住后台预热。实际正式档位诊断发现，数量、添加、真实法师入卡和升至十二级仍各核对两次，第二次全部无变化。新增实际共用检查器回归后复现失败，再补齐当前卡入口；当时三十五项定向检查及严格编译通过。最终正式页面调用次数仍需重建后测量。
3. 首次全量在新回放绑定前执行，得到 7,741 通过、24 失败、173 条件未执行；过期运行报告、当前版本锁、日志日期及 Windows 文件权限原因分开记录。绑定后的旧源树完整复验为 7,774 通过、两项 Windows 文件权限失败、162 条件未执行，不能称全部通过，也不能代替最终源树完整复验。
4. 旧读取器完整源码、原包和原依赖锁均未改。当前应用依赖锁只改变根应用的两个版本字段，完整依赖图相同；按真实新候选重新绑定当前锁指纹，保留旧源码、完整旧锁、依赖比较、篡改断言和原时限。
5. 正式构建与浏览器早期准备失败分别保留：新测试布局缺少必填字段、临时盘满、私有配置模块类型，以及导航时机。采用本轮专用临时目录，不清理其他文件；未将这些失败记成产品缺陷或通过。

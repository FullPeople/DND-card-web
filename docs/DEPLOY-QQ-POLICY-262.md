# 2026-10-09：自动部署入口接续 QQ 配置

262 的界面与原卡同步修复已发布。继续核对发现，正式 Actions 封包仍要求 QQ 为 `pending`，服务器固定入口也没有把实际 QQ 状态写入清单；线上 API 已为 `ready`，因此后续自动发布会被拒绝。

本批只修复发布工具，不改角色卡、插件、后台、数据库或 QQ 凭据。新格式 2 制品把实际 `qqLogin` 写入两份 `release.json`、制品元数据与服务器清单。固定入口核对每一层一致，发布预检和切换时继续检查实际后端版本、临时上传、IP 限额策略及 QQ 状态。预检之后发生状态漂移，必须在备份和切换前停止。

历史格式 1 仍只代表 `pending`，用于既有状态查询和恢复；不能借缺失字段推断为 `ready`。未知状态、格式与不一致的页面元数据拒绝处理。原 OIDC 身份、精确提交 CI、目录范围、制品散列、锁、备份和恢复检查保留。

候选验证包含真实临时目录中的两种状态发布、历史制品拒绝、预检后漂移、两页面状态不一致，以及实际封包。服务器升级前须对照安装记录与实际文件散列，使用已有安装器的 `--expected-installed-revision` 模式创建新备份；该模式不改 SSH 策略、不重新加载 SSH 服务，也不切换线上页面。最终安装和 Actions 实际预检结果将在本记录补充。

真实 QQ 账号扫码、真实枭熊多人房间、玩家原设备和实体触屏仍需相应环境验收，不能由发布入口检查代替。

主线浏览器检查还暴露了时序不稳定：画廊使用浏览器帧循环移动，不能仅凭原生动画列表为空就认定侧卡已经可点；赠送法术的落点需指向接收区，避免 A4 重排后落在栏目标题。相应检查现在等待实际可点区域，并使用真实接收区。离线生命值用键盘离开输入框后，还须核对 IndexedDB 中的 17 点和离线重载。原断言保留，没有放宽数值、跳过失败或修改产品行为。

离线重载时，纸面数据会先显示，编辑器运行时在启动演出结束后才加载。未就绪时，现有编辑按钮禁用，编辑请求也明确提示等待；之前的生命值检查只看到了纸面，提前发送了修改。现在先等待实际编辑按钮可用，再验证失焦提交、数据库保存与完全断网重载。

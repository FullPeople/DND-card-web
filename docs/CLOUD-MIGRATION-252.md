## 实现与边界

- 保留 251 的五页、灰色切角、A4 默认及用户已保存的布局偏好、规则核心、本机数据库和完整文件交换。没有合入未合并的 Go 后端 PR2，也没有使用单文件离线 HTML 作为服务端。
- `server/cloud` 是独立 Node + SQLite 服务；完整文档校验后原样入库，云端修订与角色内部修订分开。服务端事务限制每账号 10 张自有卡；获授权卡不计入编辑者配额。唯一随机 ID 可供访客读取；无公开目录。
- 卡主通过 QQ 号管理授权和删除。QQ 号只有经过未来身份提供方验证后才用于账号匹配，表单输入不充当身份凭据。当前发布不提供 OAuth 回调、模拟登录、注册或购买槽位接口。真实 QQ 登录申请中，公网云端登录与保存暂不可用。
- Cookie 会话、同源检查、CSRF、每次写入重新核对账号、权限和云端修订；冲突返回 409，本机草稿与基线保留。再次打开云端卡不会覆盖已有草稿。显式上传确认包含完整五页与按 ID 公开查看的说明。
- 永久槽位每个 2 元，付款未接入。展示“这是一项非常不必要的开销”“可以尝试多开账号”，并说明限制用于避免服务器被大量角色卡占满。
- 测试身份仅存在于本地测试工具与临时 SQLite；不会部署到公网数据库。未来 QQ OAuth 的 openid/unionid 不等于实际 QQ 号，不能在缺少可验证号码绑定能力时启用按号码编辑授权。

## 用户迁移

1. 在原来保存角色的浏览器打开 [旧站](https://obr.dnd.center/card/)，进入“导入 / 导出”。选择某张卡或“全部可见角色”，点击“下载 JSON”。
2. 在 [新站](https://dnd.center/card/)使用“批量导入 JSON 文件”或“导入角色 JSON”。全部校验通过后按提示确认。
3. 核对主要、特性、背景、法术、背包及资源消耗，再下载一份新站完整 JSON 备份。

旧站继续可读取、保存和导出，不强制跳转。旧域名的 Wiki 缓存和界面偏好不自动搬运。角色 JSON 保留条目身份、所选来源快照、规则包、选择、资源、头像和未知原文；禁止先清理旧浏览器站点数据。
